## 🔍 协同视角（v1.0.23+）

### 🛠️ RD 视角（实现可行性 / 估时 / 风险）
- **实现路线分叉**：用 SQL LIKE 还是单独索引？
  - LIKE：实现简单，但用户量 >10W 时性能差
  - ES：需引入 Elasticsearch（运维成本）
  - 建议：v0.4 用 LIKE（向 alice 的 v0.1-search-basic 复用）
- **estimate**：1-2 人天（含测试）
- **风险**：与 alice 的 v0.1 同时改 `src/services/search.py` → **必须协调**

### 🧪 QA 视角（边界 / 测试矩阵 / 性能）
- **边界**：空查询、特殊字符（@ + 中文）、超长输入（>200 字符）
- **测试矩阵**：3 种搜索方式 × 4 种边界 × 中英文 = 24 用例
- **性能**：500ms 阈值需要在 1000 用户数据集下验证
- **回归**：alice 的 v0.1 测试不能因本次改动失败
