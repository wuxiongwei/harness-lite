# 路径 B 文件数量硬规则例外

> 来源：Harness-Lite v1.0.10 写 quickstart 文档时破例决策

---

## 背景

路径 B（小需求）硬规则：**≤3 文件改动**。超过视为路径 A。

v1.0.10 写 quickstart 文档时改动 4 个文件：
- `docs/01-getting-started/01-quickstart.md`（新增）
- `README.md`（修死链）
- `VERSION`
- `CHANGELOG.md`

严格按规则应升 A，但认知负担明显是"小需求"。

## 决策

**批准破例**，理由：
1. 4 个文件全是**文档层**（零代码、零接口变更、零数据风险）
2. README + VERSION + CHANGELOG 是"管理开销"，不是实际交付物
3. 认知负担与小需求一致

## 后续影响

此例外暴露规则设计盲区：**没区分"代码文件 vs 管理文件"**。

## 改进方向

v1.1+ 重新定义路径 B 硬规则：
```
≤3 个**代码文件**改动 + 任意数量**管理文件**（VERSION/CHANGELOG/README）
```

或更精确：
```
≤3 个会影响运行时行为的文件 + 任意文档层文件
```

## 教训

- 规则不准 → 破例变常态 → 规则失效
- 发现破例需求时，**修规则** > 每次重新判断
