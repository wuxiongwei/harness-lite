# UC3 产物链路类验收用例

> 验证目标：产物链路可追溯，反向校验正常触发
> 注意：这是真闭环用例，需要在真实项目跑

---

## UC3.1 路径A完整链路（真闭环）

### 验收标准

`/harness-req` → 01需求 → 02设计 → 03代码 → 04测试，反向校验正常触发，4个人介入点都在。

### 验证步骤（真实项目跑）

1. 在真实项目（如 stock-make-money）启动
2. 执行 `/harness-req`，描述一个新需求
3. 观察 AI 是否：
   - 正确判定路径A
   - 创建版本目录 `docs/versions/active/v0.X-slug/`
   - 生成 01-需求.md

4. 继续走 Phase 2-4：
   - 02-设计.md（人介入1：方案确认）
   - 03-代码索引.md（implementer 执行）
   - 04-测试.md（人介入2：用例评审）

5. 验证反向校验：
   - 每阶段结束 AI 是否追问"能否回推到上游"

### 验证 prompt

```
/harness-req

我想加一个用户收藏功能，用户可以收藏喜欢的股票，
方便后续快速查看
```

### 通过条件

- 路径判定正确（路径A）
- 4个产物文件都生成
- 反向校验在每阶段结束触发
- 人介入点提示出现

## UC3.2 路径B轻量链路（真闭环）

### 验收标准

小需求只生成 01-小需求记录 + 04-验证，耗时 5-15分钟。

### 验证步骤（真实项目跑）

1. 给一个小需求
2. 观察 AI 是否判定路径B
3. 产物是否只有 2 个文件

### 验证 prompt

```
/harness-req

把首页的标题从"股票列表"改成"我的自选股"
```

### 通过条件

- 路径判定为 B
- 只生成 01-小需求记录.md + 04-验证.md
- 不生成 02-设计.md

---

## UC3.3 路径C Bug链路（真闭环）

### 验收标准

Bug修复走 复现 → 根因 → 修复 → 回归，必须有可复现的 bug case。

### 验证步骤（真实项目跑）

1. 报告一个 bug
2. 观察 AI 是否判定路径C
3. 是否先要求复现

### 验证 prompt

```
/harness-req

修复 bug：点击收藏按钮后，页面没有反应，
但是刷新页面后发现已经收藏成功了
```

### 通过条件

- 路径判定为 C
- 先生成 01-复现.md（要求可复现步骤）
- 再生成 02-根因.md
- 最后生成 03-修复.md + 04-回归.md
