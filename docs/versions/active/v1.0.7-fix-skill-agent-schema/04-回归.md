## 元发现（回流到 backlog）

### M1 · 三类元数据文件全部 schema 漂移过

| # | 元数据文件 | 修复版本 | 漂移症状 |
|---|----------|---------|---------|
| 1 | `.claude/settings.json` | v1.0.5 | alwaysAllow / matcher 对象 / action |
| 2 | `.claude/skills/*/SKILL.md` | v1.0.7 | trigger / version / 调用名 |
| 3 | `.claude/agents/*.md` | v1.0.7 | visible / invisible |

**深度根因**：所有这些 schema 都是**早期凭印象写**，没去查 https://code.claude.com/docs/en/。
**预防**：未来新增任何 Claude Code 元数据文件，**必须先查官方 docs，再在 validate.sh 加校验项**。

### M2 · "/harness:" 调用名错了所有 dogfooding 都没暴露的根因

dogfooding 期间从未真正在 claude 里敲过 skill 命令：
- v1.0.0-1.0.4：harness-lite 自己用符号链接 dogfood，但根本没进 claude REPL
- v1.0.5：进了 claude REPL 看到 settings 报错（修了），但红字消失就以为完事
- v1.0.6：加 schema 自检（只校验 settings）
- v1.0.7：审计同源 bug 才发现

→ **dogfooding 协议必须包含**：每个版本至少敲一次 skill 命令验证生效。已写入 backlog/proposals.md。

### M3 · skill description 写得好不好决定自动触发能不能工作

新格式把 keywords 融入 description，Claude 是否能正确选中 skill 完全靠 description 写得好不好。这是个**长期演化问题**，不是一次能验证完。

→ 加入 backlog：v1.1 时统计 skill 自动触发命中率。

### M4 · validate.sh 已经从"装完检查"演变为"schema 防线"

v1.0.6 之前：仅检查文件存在性
v1.0.6 后：+ settings.json schema 5 条不变式
v1.0.7 后：+ skill / agent frontmatter 4 类校验 + 调用名校验

→ **validate.sh 已是 Harness-Lite 的核心质量基础设施**。下次有 schema 漂移类 bug，第一动作必然是 "validate.sh 能不能抓到？"。
