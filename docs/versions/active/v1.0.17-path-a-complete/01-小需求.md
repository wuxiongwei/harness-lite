## 1. 业务诉求

### 问题
`templates/templates/path-a/` 只有 4 个阶段文件：
- 01-需求.md
- 02-设计.md
- 03-代码索引.md
- 04-测试.md

对比：
- path-b 有 2 个阶段（01-小需求 + 04-验证）
- path-c 有 4 个阶段（01-复现 + 02-根因 + 03-修复 + 04-回归）

**path-a 缺"收尾"阶段**——测试完了就没了，实际上需求完成后需要：
- 确认交付清单（什么交付了、什么没交付）
- 记录遗留问题（已知缺陷 / 技术债 / 未实现需求）
- 复盘并沉淀到 wiki

### 价值
补 05-完成.md 后：
- 路径 A 流程完整（需求 → 设计 → 代码 → 测试 → 完成）
- AI 在走 path-a 时有明确"收尾"指引
- 与 path-b / path-c 对称（每条路径都有"收尾"阶段）
