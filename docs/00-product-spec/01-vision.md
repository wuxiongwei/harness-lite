# 产品愿景

> Harness-Lite 想要变成什么？为什么这个世界需要它？

---

## 一、一句话愿景

**让任何2-5人的小团队，都能在30分钟内建立起AI协作的工程化共识。**

---

## 二、问题背景

### 2.1 AI编程进入新阶段

2024年开始，AI编码工具（Claude Code / Cursor / Copilot等）在生产环境快速普及。但实际使用中暴露出系统性问题：

```
表层现象 ←─── 深层根因
─────────     ─────────
AI产出"看人下菜"     缺少团队共识
     ↑
代码风格不统一       缺少自动加载的约束
     ↑
小需求也写PRD累       流程一刀切
     ↑
单测过了上线就崩      验收层级混淆
     ↑
踩过的坑反复踩        知识无沉淀机制
```

### 2.2 现有工具的不足

| 现有方案 | 不足 |
|---------|-----|
| **大公司Harness方案** (如PSC Harness) | 太重：38个skill + 19个角色，对小团队过度 |
| **个人化TDD框架** (如alexop.dev) | 太窄：只覆盖测试，不解决协作 |
| **AI编辑器内置规则** (如.cursorrules) | 太弱：只解决格式，不解决流程 |
| **企业级DevOps平台** (如GitLab CI) | 太硬：流程刚性，AI友好度差 |

**市场空白**：**2-5人小团队没有合适的AI协作工程化方案**。

### 2.3 目标用户的真实困境

```
"我们就3个人，搞那么重的流程不现实，
 但完全没规范又怕失控。
 
 想要一套：
 - 30分钟能装好
 - 半天能上手
 - 能管住AI不让它跑偏
 - 但又不会拖慢我们速度
 
 这种东西真的存在吗？"
```

**Harness-Lite就是为这个问题诞生的。**

## 三、产品愿景

### 3.1 三年期目标

```
Year 1 (2026): 验证可行性
  ├── MVP在你团队跑通
  ├── 5-10个朋友团队试用
  └── 形成可复制的安装包

Year 2 (2027): 建立影响力
  ├── 开源/部分开源
  ├── 100+团队使用
  └── 形成最佳实践案例库

Year 3 (2028): 成为标准
  ├── 小团队AI协作的事实标准之一
  ├── 与主流AI工具集成
  └── 探索商业化可能
```

### 3.2 终极愿景

```
"任何小团队从想用AI协作，到建立完整工程化体系，
 不应该需要超过 1 天。"
```

## 四、核心价值

### 4.1 让小团队享受工程化红利

大厂享有的工程化能力（CLAUDE.md规范、产物链路、知识沉淀），**小团队不应该被排除在外**。

Harness-Lite承诺：**90%的工程化效果，10%的实施成本**。

### 4.2 站在巨人的肩膀上

我们不重新发明轮子。Harness-Lite站在以下方法论的肩膀上：

```
《AI编程时代的软件工程V1.0》
        ↓
  上下文工程 + 反馈回路
        ↓
PSC Harness（完整版）
        ↓
  7工序25活动 + 三层定位
        ↓
AI-TDD-Harness（专项实战）
        ↓
  路径分级 + 多Agent + 验收分层
        ↓
   Harness-Lite
   （为小团队精炼）
```

### 4.3 渐进演进

Harness-Lite不是"装上就完美"，它是会**陪伴团队成长**的：

```
Day 1   → 装好，跑通工作流
Week 1  → 团队接受，形成习惯
Month 1 → 知识库开始沉淀
Month 3 → AI产出质量明显提升
Year 1  → 团队从Small升级到Medium
```

## 五、设计哲学

### 5.1 三个不

```
❌ 不替代人 — AI是放大器，不是替代者
❌ 不增加流程 — 是换工具，不是加流程
❌ 不锁死方案 — 任何环节都可定制
```

### 5.2 三个要

```
✅ 要让AI听话 — 通过约束让AI产出可预测
✅ 要让团队对齐 — 共识入版本库，不靠口口相传
✅ 要让知识沉淀 — 踩过的坑结构化保存
```

### 5.3 一句话设计原则

> **"约束 AI，赋能人"**

## 七、不变的核心

无论产品如何演进，以下内核不变：

```
1. 简单 → 5分钟装好，30分钟上手
2. 自适应 → 路径分级，不一刀切
3. 反馈回路 → 多视角验证，反向校验
4. 沉淀友好 → 知识不靠人脑记
5. 可演进 → 任何决策都可调整
6. 尊重团队 → 不强加流程，只提供能力
```
