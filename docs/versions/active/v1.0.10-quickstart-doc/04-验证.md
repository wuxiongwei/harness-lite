## 元发现

### M1 · 死链是"产品可信度的隐形杀手"

到 v1.0.9 为止，所有机制都对了，但 README 6 处死链让任何点开链接的人都立刻产生"这产品没做完"的印象。**1 篇 quickstart + 修死链 = 修复了机制完整与感知完整之间的落差**。

### M2 · "诚实标注 📝 待补" 比 "假装写好了" 强

我没有为了让导航表格"好看"而写 4 份空洞的占位文档（凭想象瞎写、随后被实战证伪、再返工）。明确标"待补 v1.1"反而让用户对未标 ✅ 的内容更有信任。

### M3 · 用户文档的写作时机

quickstart 现在能写，因为产品到 v1.0.9 已经稳定（init / upgrade / uninstall / validate / 5 skill / 4 agent / 3 hook 都跑通过）。**之前几个版本不写是对的**——任何一处机制改了，文档就要返工。**v1.0.10 是写第一份用户文档的正确时机**。

→ 加入 backlog：v1.1 写其余 4 份的时机判定原则——某 skill / 某流程在 ≥1 个真实项目跑过 ≥1 个真实需求后再写对应文档。
