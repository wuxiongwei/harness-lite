# 02-根因.md · v1.0.27

> **路径C P0 · 阶段2/4**

---

## 1. 直接根因

AI 报"完美！部署已全部完成！"时，**严格按 H-L v1.0.26 协议自检都过得去**：
- ✅ commit / 部署 / API 200 / 测试通过 / 文档齐全
- ✅ harness-review 5 维度一致性审计通过
- ✅ 05-完成 交付清单按模板填写

但**用户无法使用**（前端没集成 / 无入口）。

**根因**：H-L 协议没把"用户故事真闭环"作为硬卡点。

---

## 2. 根因背后的根因（4 个 gap）

### Gap 1 · principles §6 完整交付铁律缺"用户视角"

现有 §6：
```
完整交付链：编码 → 自测 → review → 联调 → 文档同步 → 残留清理
```

**缺**：
- "用户从哪里开始用这个功能？"
- "用户能走完整路径吗？"
- "前端组件写了但没集成 = 未完成"

→ AI 做完"编码 + 自测 + review + 文档"就报"完成"，按协议没错，但用户用不了。

### Gap 2 · harness-review 5 维度缺"AC ↔ 用户路径"

现有 5 维度：
1. 需求 ↔ 设计
2. 设计 ↔ 代码
3. 代码 ↔ 测试
4. 测试 ↔ 需求（反向）
5. 代码 ↔ 规则

**缺**：
- 第 6 维：AC ↔ 用户路径真验证

→ 审计通过"代码一致性"，没审计"功能真能用"。

### Gap 3 · 05-完成 模板缺"用户路径自检"段

现有交付清单：
- ✅ 需求文档 / 设计文档 / 代码实现 / 单测 / 集成测试 / 文档更新

**缺**：
- "每条 AC 用户从哪里开始 → 中间路径 → 结果可观测"

→ AI 按清单勾 ✅，但没自问"用户从哪进、到哪用"。

### Gap 4 · validate.sh 没检查用户故事覆盖

现有 8 维防回归：
- 文件 / 目录 / settings / skill / 占位符 / hook if / wiki / §14 schema

**缺**：
- 第 9 维：01-需求 含用户故事 → 05-完成 必须含"用户路径自检"段

→ 静态防回归网没卡住"AC 未闭环"的版本。

---

## 3. 为什么协议层没发现（诚实审视）

H-L v1.0.21-26 协议层迭代重心：
- v1.0.21 §13 决策学习（个人偏好层）
- v1.0.23 §14 多人协同（团队协作层）
- v1.0.24 / v1.0.25 / v1.0.26 实施层强约束（让协议真触发）

**但始终没覆盖**：
- "完成" = 用户能用（不是代码能跑）
- 用户故事 = 硬卡点（不是可选的"补充说明"）

**原因**：
- H-L 主要聚焦"AI 自己怎么做好"（个人 / 团队 / 实施层）
- 缺"AI 做完的东西用户能不能用"这个维度

**这是产品定位的盲区**——H-L 是"AI 工作方法论"，但没把"用户能用"作为方法论的一部分。

---

## 4. 修复方案（4 件套，用户拍板 A）

### 4.1 修复 1 · principles §6 加"用户故事真闭环"硬约束

§6.1 用户故事真闭环硬约束：
- 报"完成"前必做的 3 个自问（用户从哪开始 / 中间路径 / 最终看到什么）
- 用户故事 = AC = 硬卡点
- 后端 API + 前端集成的特殊情况（前端集成 = 把组件接到真实页面 / 路由）
- 4 条自检（组件代码写完 / 集成到哪个页面 / 路由注册 / 真实环境能走通）

协议层硬约束 + 自检清单 13 条（12 条 → 13 条）。

### 4.2 修复 2 · harness-review 加第 6 维度

维度6：AC ↔ 用户路径真验证（v1.0.27 起）：
- 检查每个 AC：入口 / 中间路径 / 结果可观测 / 端到端联调
- 严格判定：任一缺失 / 只有代码但没集成 = 不通过
- 高风险关键词（"组件代码已写" / "API 已部署" / "测试通过"）

审计层硬卡点。

### 4.3 修复 3 · 05-完成 模板加"用户路径自检"段

新段在第一位（硬卡点）：
- 每条 AC 必须回答：用户从哪开始 / 中间路径 / 结果可观测 / 真实验证了
- 前端 + 后端场景特殊自检（4 条）
- 反面案例（违规示例）

模板层强约束。

### 4.4 修复 4 · validate.sh 加第 9 维

用户故事真闭环检查（v1.0.27+）：
- 01-需求 含用户故事 / AC → 05-完成 必须含"用户路径自检"段
- 缺失 → 报错（§6.1 违规）

防回归网兜底。

## 5. 元发现

### M1 · 协议层产品的"用户能用"盲区

H-L v1.0.0-26 迭代聚焦：
- path-a 流程（v1.0.0-10）
- 决策学习（v1.0.21-22）
- 多人协同（v1.0.23-26）

**盲区**：
- "AI 做的东西用户能不能用"

这不是某个协议遗漏，是**产品定位的根本盲区**——H-L 是"AI 工作方法论"，但没把"交付给用户"作为方法论终点。

→ 加入 backlog：H-L 协议层必须覆盖"AI 做 → 用户用"的完整链路，不能只覆盖"AI 怎么做"。

### M2 · 用户故事 ≠ 可选的"补充说明"

很多项目把 01-需求.md 用户故事当"可选的补充说明"——重点是设计 / 代码 / 测试，用户故事只是"前置文档"。

**v1.0.27 修正**：
- 用户故事 = AC = 硬卡点
- 不是"补充说明"，是"完成"的定义

这是产品哲学的根本转变。

### M3 · "测试通过" ≠ "功能能用"

测试跑的是单元 / API / 集成层，**不是用户路径**。

```
测试通过 = 代码逻辑正确
         ≠ 用户能从入口走到结果
```

v1.0.27 补的是这个 gap：harness-review 维度6 / 05-完成 用户路径自检。
