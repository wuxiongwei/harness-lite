## 1. 触发动机

v1.0.5/1.0.7/1.0.8/1.0.11 修过 4 次 schema 漂移类 bug。共性都是"凭印象写、没在真 claude 实测"。本轮主动审计 3 个 hook 脚本本身：

```bash
# 1. 静态语法
✅ block-push.sh / pre-commit-test.sh / distill-prompt.sh

# 2. 单独触发
✅ block-push.sh exit 2 + stderr
✅ distill-prompt.sh exit 0 + 提示文本
✅ pre-commit-test.sh 在无测试框架时 exit 0
```

→ 静态都正常。但**真正问题在 settings.json 的 if 字段**——查官方 docs 才发现语法错。

---

## 2. 证据

### 证据 1 · settings.json 中 if 写法

```json
{ "if": "Bash(git commit*)" }   ← 我写的（v1.0.5 起）
{ "if": "Bash(git push*)" }     ← 我写的
```

### 证据 2 · 官方文档（https://code.claude.com/docs/en/hooks）

```json
{ "if": "Bash(rm *)" }         ← 官方示例（带空格）
{ "if": "Bash(git *)" }
{ "if": "Bash(git push *)" }
```

文档明确写：
> "if uses permission rule syntax to match against the tool name and arguments together, so 'Bash(git *)' runs when any subcommand of the Bash input matches 'git *'"

### 证据 3 · 同根

跟 v1.0.7 完全同根：**写完没在真 claude REPL 实测过**——任何凭印象写的字段格式都可能错。

### 顺带发现 · block-push.sh 是过度设计

| 防护层 | 已有 |
|-------|-----|
| principles.md | 明文规定"AI 不主动 commit/push" |
| permissions.deny | `Bash(git push --force *)` 等危险 push 已封 |
| block-push.sh | 拦所有 push |

**问题**：hook 拦不区分"AI 主动 push" vs "用户让 AI 帮 push"——后者明明是合理场景但被一刀切。**三层防护中第三层是冗余 + 扰民**。
