# bash 多字节边界踩坑

> 来源：Harness-Lite v1.0.4 / v1.0.5 / v1.0.9 三次重复踩坑

---

## 现象

macOS bash 3.2 下，中文字符紧贴 `$VAR` 变量时，输出出现字节截断：

```bash
echo "版本 $VERSION..."
# 预期：版本 1.0.5...
# 实际：版本 v�...
```

## 根因

bash 3.2 的变量替换在遇到多字节 UTF-8 字符时，边界判定有 bug。`$VAR` 前后如果是中文且不用大括号显式分界，bash 会在字节级别错误切分。

## 规避方法

**强制用 `${VAR}` 大括号包裹**，让 bash 明确知道变量边界：

```bash
# ❌ 错误
echo "版本 $VERSION..."

# ✅ 正确
echo "版本 ${VERSION}..."
```

## 适用场景

- macOS / BSD 系统的 bash 3.x
- 变量前后是中文、日文、韩文等多字节字符
- Linux bash 4.x+ 一般没这个问题，但为了可移植性仍建议统一用 `${VAR}`

## 教训

**凡是脚本中 `$VAR` 前后可能出现中文，强制用 `${VAR}`**——不要等出现乱码再修，一开始就写对。
