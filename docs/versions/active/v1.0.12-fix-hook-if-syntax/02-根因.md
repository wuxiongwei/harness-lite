## 1. 直接根因

### 1.1 if 字段格式凭印象写

v1.0.5 修 settings.json 时，把 hook 拦截写成 `if: Bash(git commit*)`——**没去查官方文档**。当时只确认了 `matcher` 是字符串、`hooks` 是数组（v1.0.5 报错信息直接驱动），没看 `if` 字段格式。

### 1.2 block-push.sh 设计时未考虑用户主动场景

v1.0.5 把 push 拦截从 settings.json 抽出来变独立脚本时，**只想"拦 AI"**，没想到：
- principles.md 已经规定（规则层）
- permissions.deny 已经拦（权限层）
- hook 又拦一次（执行层）→ **三层冗余**

且 hook 无法区分 AI 主动 vs 用户授意——结果是**用户授意 push 也被拦**，扰民。

---

## 2. 根因背后的根因

### 2.1 v1.0.7 同根 dogfooding 盲区

v1.0.7 修 skill / agent schema 时识别出元发现：**dogfooding 期间从未在真 claude REPL 敲过 skill 命令**。当时承诺 "下次必敲"。但 v1.0.5 → v1.0.11 之间**hook 也从未在真 claude 触发过**——同根。

→ 根因升级：**dogfooding 协议必须包含 "凡是被 Claude Code 加载的元数据 / 配置 / hook，都必须在真 claude 触发一次"**。

### 2.2 防护层数量与冗余度的设计盲区

block-push.sh 是把"防 AI push"叠到第 3 层。但 3 层防护中每多一层就要：
- 多 1 处可能配错的地方
- 多 1 处用户感知到的拦截信号
- 多 1 处需要维护的代码

**核心问题**：每加一层防护时**没有问"前面已有几层"**。这不是"安全多多益善"——是过度治理。

---

## 3. 修复方案

### 3.1 主修 1 · settings.json if 字段格式

```diff
- "if": "Bash(git commit*)"
+ "if": "Bash(git commit *)"

- "if": "Bash(git push*)"      // 这一行连 hook 都删
```

### 3.2 主修 2 · 删除 block-push.sh

- 删 `templates/.claude/hooks/block-push.sh`
- 删 settings.json 里调用它的 hook 段
- 修 uninstall.sh 保留删除逻辑（让升级用户能清掉老安装的残留）

### 3.3 横向预防 · validate.sh 第 6 条不变式

```bash
# jq regex 检测 `Bash(xxx*)` 缺空格写法
bad_if=$(jq -r '
    [.hooks.PreToolUse, .hooks.PostToolUse] | flatten | map(.hooks[]?.if // empty)
    | map(select(test("\\([^)]*[a-zA-Z]\\*\\)")))
    | .[]
' .claude/settings.json)
```

未来任何人添加新 hook 凭印象写错格式 → 下一次 validate.sh 立即抓。

### 3.4 现场修 · stock_make_money

- settings.json 整个覆盖（含 `_version → 1.0.12`、新 if 格式、删 block-push 段）
- 删 `.claude/hooks/block-push.sh`

### 3.5 不做（避免过度治理）

- ❌ 不写"hook 集成测试脚本"——单独验 hook 在真 claude 触发是大工程，留 v1.1+ 视情况
- ❌ 不重构所有 hook 为某种声明式格式——当前 3 个 hook 工作得挺好
