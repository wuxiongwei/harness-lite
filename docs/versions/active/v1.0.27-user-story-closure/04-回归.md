## 元发现

### M1 · 协议层产品的"用户能用"盲区

H-L v1.0.0-26 迭代聚焦：
- path-a 流程（v1.0.0-10）
- 决策学习（v1.0.21-22）
- 多人协同（v1.0.23-26）

**v1.0.27 补的根本盲区**：
- "AI 做的东西用户能不能用"

这不是某个协议遗漏，是**产品定位的根本盲区**——H-L 是"AI 工作方法论"，但没把"交付给用户"作为方法论终点。

→ 加入 backlog：**H-L 协议层必须覆盖"AI 做 → 用户用"的完整链路**，不能只覆盖"AI 怎么做"。

### M2 · 用户故事 = 硬卡点（不是"补充说明"）

很多项目把 01-需求.md 用户故事当"可选的补充说明"。

**v1.0.27 修正**：
- 用户故事 = AC = 硬卡点
- 不是"补充说明"，是"完成"的定义

这是**产品哲学的根本转变**。

### M3 · 4 件套模式再次验证

v1.0.27 和 v1.0.24 / v1.0.25-final 同源：
- 协议层（principles）
- 审计层（harness-review）
- 模板层（05-完成）
- 防回归层（validate）

**4 件套 = H-L 协议层产品修复的标准范式**。

沉淀：
- v1.0.24 §13 三件套（协议 + 实施约束 + 示例）
- v1.0.26 §14 三件套（同上）
- **v1.0.27 §6.1 四件套（协议 + 审计 + 模板 + 防回归）**

→ 未来协议层修复优先考虑"几件套齐备"，不能只改协议本身。
