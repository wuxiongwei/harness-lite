## 2. 实际发现的问题

### 问题 A · skill 调用名写错（5/5 全部）

我以为调用方式是 `/harness:req`（冒号分隔），事实上：
- 冒号语法仅用于 **plugin 命名空间**（`/plugin-name:skill-name`）
- 项目级 skill 的调用名 = **目录名**

正确调用名应该是 `/harness-req`（连字符），目录已经是 `harness-req/`，但所有文档都写成 `/harness:req`。

**文档/脚本引用统计**：49 处在 `.claude/` 内部 + 8 处在外部（CLAUDE.md / init.sh / README.md）= **57 处需要替换**。

### 问题 B · skill frontmatter 字段不存在（5/5 全部）

```yaml
trigger:                          # ❌ Claude Code 不认这个字段
  keywords: [...]
  patterns: [...]
version: 1.0.0                    # ❌ 不存在
```

官方支持的字段（按 https://code.claude.com/docs/en/skills）：
- `name` / `description`（仅 description 推荐）
- `disable-model-invocation` / `user-invocable`
- `allowed-tools` / `disallowed-tools`
- `model` / `effort` / `argument-hint` 等

**自动触发**靠的是 `description` 写得好，让 Claude 在合适场景主动选用。**显式调用**就是 `/skill-name`，没有"keywords/patterns"这种东西。

### 问题 C · agent frontmatter 字段不存在（4/4 全部）

```yaml
visible:                          # ❌ 自造字段
  - 用户输入
  - .claude/templates/**
invisible:                        # ❌ 自造字段
  - src/main/**
```

官方支持的字段（按 https://code.claude.com/docs/en/sub-agents）：
- `name`（必填）/ `description`（必填）
- `tools` / `disallowedTools`（**这才是限制可见范围的正确字段**）
- `model` / `permissionMode` / `maxTurns` / `skills` / `mcpServers` / `hooks` / `memory` / 等

`visible` / `invisible` 是把 markdown 注释里的"建议"误植入 frontmatter——这些约束应该写在 **system prompt body**（即 yaml 之后的正文）里，而不是 frontmatter。

## 3. 影响面

| 维度 | 实际影响 |
|------|---------|
| 用户启动 claude | **不报错**（不像 v1.0.5 settings 那样直接弹红框）——schema 不严格的字段会被忽略 |
| skill 自动触发 | 失效——Claude Code 不认 `trigger`，只能靠 description 触发 |
| skill 显式调用 | `/harness:req` **404**——Claude Code 找不到这个名字 |
| 用户实际能用的命令 | **`/harness-req`、`/harness-design`、`/harness-impact`、`/harness-review`、`/harness-test-ci`** |
| agent 可见范围限制 | 不生效——`visible/invisible` 被忽略，agent 实际继承所有工具 |
| 文档全部错误 | 所有教用户 `/harness:req` 的文档都误导用户 |

### 关键证据

```bash
$ ls templates/.claude/skills/
harness-design  harness-impact  harness-req  harness-review  harness-test-ci

# 目录名是 harness-req（连字符），所以调用名 = /harness-req
# 但所有文档教用户敲 /harness:req
```
