## 用户路径自检（v1.0.27 起 · principles §6.1 硬约束）

> **为什么放第一段**：这是"完成"的硬卡点——答不出这些问题 = 未完成。

每条用户故事 / 验收标准（AC）必须回答：

| AC | 用户从哪开始？（入口） | 中间路径是什么？| 用户最终看到什么？（结果）| 真实验证了？ |
|---|-------------------|--------------|---------------------|-----------|
| AC1: ... | 【填写】哪个页面 / 按钮 / API | 【填写】点击后 → 调用 XX API → ... | 【填写】页面变化 / 数据展示 / 日志 | ✅ 已真测 / ⏳ 待真测 |
| AC2: ... | ... | ... | ... | ... |

**填写要求**：
- "入口"必须具体：不能写"前端页面"（哪个页面？），不能写"API"（哪个端点？）
- "中间路径"必须完整：前端→后端→数据库，每一环都要列
- "结果"必须可观测：用户 / 调用方能看到 / 感知到
- "真实验证"必须诚实：✅ 表示已经真测过或真演示过，⏳ 表示理论上应该可以但还没真测

**反面案例（违规示例）**：

| AC | 入口 | 中间路径 | 结果 | 判定 |
|---|-----|---------|------|------|
| AC1: 用户点击关注按钮 | ❌ "前端组件已写" | ❌ "API 已部署 200" | ❌ "测试通过" | **未完成**（缺集成） |
| AC2: 持仓自动同步 | ✅ cron 任务配置 | ✅ 调用 sync_holdings_job.py | ✅ 数据库有记录 | **完成** ✅ |

**前端 + 后端场景的特殊自检**：

```
[ ] 前端组件代码写了？
[ ] 组件集成到哪个页面了？（StockDetail.tsx / App.tsx / ...）
[ ] 路由注册了？（App.tsx 的 <Route path="..." />）
[ ] 真实环境能从用户入口走到这个组件？（不是理论上能，是真走过一遍）
```

四项全 Yes → AC 真闭环 ✅

## 决策回顾（v1.0.21+ · principles §13）

> 本段自动触发：读取本次迭代的决策日志，批量授权哪些以后别问。

### 执行流程

1. **读取本次迭代决策**：
   ```bash
   Read .claude/decision-log.md
   过滤本次版本 ID 的条目（状态 = ⏳ 待复盘）
   ```

2. **如有 N > 0 条 → 触发批量授权对话**：
   ```
   🔍 本次迭代被询问的决策（N 条）：
   
   [1] {决策标题 1}（你选了 {选择}）
   [2] {决策标题 2}（你选了 {选择}）
   ...
   
   对每条选择处理：
   - [a] 以后别问（写入 auto-decide）
   - [s] 继续问（保留询问）
   - [d] 删除记录（不学习）
   
   请输入：1=a,2=s,3=a 或 all=a 或 quit
   ```

3. **用户选择处理**：
   - 选 `a` → 写 `.claude/auto-decide.md` 一条 + 改 decision-log 状态为 ✅
   - 选 `s` → 改状态为 🔁 保留询问（下次仍问）
   - 选 `d` → 改状态为 🗑 已删除
   - `quit` → 全部不动（下次仍触发）

4. **清理 decision-log**：
   复盘后，将本次状态非 ⏳ 的条目从 decision-log.md 移除（保留追溯靠 auto-decide.md 的"来源"字段）。

### 示例输出

```
✓ 已写入 .claude/auto-decide.md：
  - 表格格式 → Markdown 表
  - commit message 格式 → feat: [模块] - ...

✓ 保持询问：
  - 模块拆分粒度（项目特性强相关，每次都问）

📝 撤回任何授权：编辑 .claude/auto-decide.md
```
