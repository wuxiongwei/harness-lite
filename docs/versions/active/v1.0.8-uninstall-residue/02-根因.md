## 1. 直接根因

`uninstall.sh` 把卸载清单**硬编码**在脚本里，每次新增 skill / hook 时**忘了同步更新**。

```bash
# uninstall.sh（v1.0.7 状态）
[ -d ".claude/skills/harness-req" ] && rm -rf ".claude/skills/harness-req"
[ -d ".claude/skills/harness-design" ] && rm -rf ".claude/skills/harness-design"
[ -d ".claude/skills/harness-review" ] && rm -rf ".claude/skills/harness-review"
# ❌ 缺 harness-impact / harness-test-ci
# ❌ 完全没有 hooks/ 那段
```

---

## 2. 根因背后的根因

### 2.1 缺"装什么 → 卸什么"对称约束

`init.sh` 装的内容来自 `templates/.claude/`（动态——目录里有什么就装什么）。
`uninstall.sh` 卸的内容是**手写硬编码列表**——必然漂移。

→ **不对称**：装是动态的，卸是静态的。

### 2.2 没有 manifest

CHANGELOG 早期设计提过 `manifest.json` 跟踪安装文件，但没实现。这次问题就是 manifest 缺位的代价。

### 2.3 install→uninstall 循环测试缺位

如果有"装一遍卸一遍"的回归脚本，每次新 commit 都跑一次，残留立刻暴露。但目前没有。

---

## 3. 修复方案

### 3.1 主修：补全 uninstall.sh 清单（短期）

直接在 uninstall.sh 加上：
- `skills/harness-impact/`
- `skills/harness-test-ci/`
- `hooks/pre-commit-test.sh`
- `hooks/block-push.sh`
- `hooks/distill-prompt.sh`
- 末尾 `rmdir .claude/hooks/`

预告文案同步：3 skill → 5 skill + 新增 hook 脚本说明行。

### 3.2 不做（避免过度治理）

- ❌ 不引入 manifest.json（写入时机、版本兼容、读写一致都得设计，是大工程）
- ❌ 不重构 uninstall.sh 为"扫 templates/ 倒推"（templates 路径跟 uninstall 现场路径有微妙差异，纯映射不安全）
- ❌ 不写自动化 install→uninstall 回归脚本（v1.0.9+ backlog，单独需求）

→ **本次只做最小修复 + 实测一次干净循环**。manifest / 自动回归延后。

### 3.3 预防（这次顺手做）

把"加新 skill / hook 时同步更新 uninstall.sh"写到 backlog/proposals.md 作为 dogfooding 协议补充项。
