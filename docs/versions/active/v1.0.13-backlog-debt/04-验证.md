## 元发现 M1 · "AI 说了要做 vs 真实没做" 是结构同构 bug

| 同根维度 | schema 漂移 | backlog 欠款 |
|--------|-----------|------------|
| 表象 | 写代码时凭印象、单点改 | 写复盘时口头承诺、不落地 |
| 根因 | 没建立"加新东西必同步"回路 | 没建立"说了必写"回路 |
| 解药 | validate.sh 5 维自检 | 提交前 grep 复盘里"已加入 backlog"是否真在 backlog/ |

发版前 dogfooding 协议升级到强制版后（已加入 proposals.md），下次再写"已加入 backlog"必须当场落地，否则 commit 前自检脚本拦下。

## 元发现 M2 · 复盘里的"承诺"性表达需要绑定到文件操作

写 "已加入 backlog/proposals.md" 这句话本身**不会**让条目真的进入 proposals.md。要么：
- 写复盘的同一动作里立刻 Edit proposals.md（强行绑定）
- 或者 commit hook 检查"复盘里出现 '已加入 X' 但 X 文件没对应改动" → 拦下

已加入 backlog 自身（套娃）：**"复盘检查脚本"——确保未来任何 04-*.md 出现"已加入 backlog"时 backlog/ 必须有对应改动**。

## 元发现 M3 · 用户反馈是首要信号

stock "运行运行就停了" 是首个真实项目报告的实战现象。和我之前主动审计找出来的 11 个 bug 不同：
- 主动审计找出的 bug：可以等下个版本修
- 用户反馈的现象：必须立刻有归宿（即使不修，也要记录）

→ 加入 backlog/proposals.md "Stock_make_money 实战观察清单" 持续记录。
