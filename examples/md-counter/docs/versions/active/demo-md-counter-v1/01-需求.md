## 1. 业务背景与动机

### 1.1 用户场景

文档写作者（技术博主、产品经理、开发者）需要快速了解 markdown 文档的统计信息：
- 字数（评估阅读时长）
- 行数（评估篇幅）
- 链接数（评估外部依赖）

现有工具：`wc` 只能统计字符数，不识别 markdown 语法；在线工具需要上传文件（安全顾虑）。

### 1.2 为什么要做

**目标**：提供一个**本地化、轻量、精准**的 markdown 统计命令行工具。

**不做的话会怎样**：用户要么手动统计（耗时），要么用不精准的 `wc`（链接 URL 也算字数）。

## 2. 功能需求

### 2.1 核心功能

| # | 功能点 | 说明 | 优先级 |
|---|-------|------|--------|
| F1 | 读取 markdown 文件 | 支持相对路径 / 绝对路径 | P0 |
| F2 | 统计中文字数 | 纯文本内容（排除代码块 / URL） | P0 |
| F3 | 统计英文单词数 | 按空格分隔 | P0 |
| F4 | 统计行数 | 总行数（含空行） | P1 |
| F5 | 统计链接数 | `[text](url)` 格式 | P1 |
| F6 | 输出到终端 | 可读格式 | P0 |

### 2.2 非功能需求

| 维度 | 要求 |
|-----|------|
| 性能 | 100KB 文件 < 100ms |
| 兼容性 | Python 3.8+ |
| 可测试性 | 单测覆盖率 ≥ 80% |
| 可维护性 | 代码 < 200 行 |

### 2.3 边界与约束

**做什么**：
- ✅ 支持标准 markdown（CommonMark）
- ✅ 命令行工具（stdin/file 输入）
- ✅ 输出统计数据到 stdout

**不做什么**：
- ❌ 不支持 GFM 扩展语法（表格 / 任务列表）
- ❌ 不做 GUI
- ❌ 不做实时监控
- ❌ 不做文件批量处理（v0.1 只处理单文件）

## 3. 用户故事

### US1 · 基础统计（P0）
```
作为 文档写作者
我想 运行 `mdcounter README.md`
以便 看到文档的字数 / 单词数 / 行数 / 链接数
```

**验收标准**：
- [ ] 输入：`mdcounter README.md`
- [ ] 输出格式：
  ```
  File: README.md
  ─────────────────
  Chinese chars:  1234
  English words:  567
  Total lines:    89
  Links:          12
  ```

### US2 · stdin 输入（P1）
```
作为 管道用户
我想 `cat doc.md | mdcounter`
以便 在管道中使用
```

**验收标准**：
- [ ] 支持 stdin（无文件参数时）
- [ ] 输出格式同 US1
