## 元发现

### M1 · 文档时机

v1.0.10 立的"等真实项目实战暴露痛点再写文档"原则正确。强行在 v1.0.10 写就会：
- 凭想象写"理想用法"
- v1.0.11/12/15/17/19/21 协议变化后频繁返工
- 写出来用户也用不起来

**正确时机**：
- v1.0.20 md-counter 示例完成后 → 有真实使用案例
- v1.0.21 协议层落地 → 内容稳定
- task #9 等了 12 个版本 → 现在写有依据

### M2 · 文档统一模板

5 篇 skill 手册用同一 9 段结构（定位 / 场景 / 调用 / 范例 / 决策点 / 做什么不做什么 / FAQ / 协作 / 进阶）。

价值：
- 用户不需要每篇都重新适应不同结构
- 维护时不会风格漂移
- 新加 skill 直接套模板（v1.1+ 加 skill 时统一加手册）

→ 加入 backlog/proposals.md：未来加新 skill 必须同步加手册（用同一 9 段模板）。

### M3 · 决策学习指南是协议层产品的关键

v1.0.21 协议层改动如果**没有用户指南**：
- 用户不知道 .claude/decision-log.md 是什么
- 不知道 05-完成 阶段会触发批量授权对话
- 看到产物末尾 "ℹ️ 已使用 AI 自决项" 困惑

→ 协议层产品必须有"使用指南"匹配。这是产品方法论新发现。
