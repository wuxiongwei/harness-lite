## 元发现（回流到 backlog）

### M1 · validate.sh 应该校验 settings.json 能被 claude 加载

当前 `validate.sh` 只检查文件存在性。建议 v1.0.6 增加：
```bash
# 用 jq 校验 schema 关键字段
jq -e '.permissions.allow | type == "array"' .claude/settings.json
jq -e '.hooks.PreToolUse[0].matcher | type == "string"' .claude/settings.json
```

或更好：调用 `claude --dry-run` 之类（如果存在）触发 schema 校验。

### M2 · dogfooding 没暴露这个 bug 的根本原因

harness-lite 自身用符号链接 `.claude → templates/.claude`，但开发期一直没在 harness-lite 自己的目录里启动 `claude`，导致 settings 加载从未被验证过。

→ 加入 dogfooding 协议：每个版本必须在 harness-lite 根目录启动一次 `claude` 看是否有 Settings Error。

### M3 · 应该有"装完一键自检脚本"

stock 装完用户手动跑 `claude` 才发现问题。建议把 `claude --version` / settings 校验整合进 `validate.sh`。

→ 三条都登记到 `backlog/proposals.md`。
