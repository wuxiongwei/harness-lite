## 关键代码

### `upgrade.sh` 6 阶段

```
Step 1：前置检查（is git repo + is HL installed + 提取旧版本号）
Step 2：版本对比（已最新 → exit 0）
Step 3：备份（.harness-lite-upgrade-backup/{ts}/）
Step 4：覆盖 H-L 管理范围（rules / skills / agents / hooks / templates / settings.json）
Step 5：CLAUDE.md 头部版本号 sed 替换
Step 6：跑 validate.sh 兜底（不阻塞，仅 warn）
```

### tech-stack-rules.md 例外处理（实施时新增决策）

```bash
# rules 全部覆盖，但 tech-stack-rules.md 是 init 时按用户技术栈渲染过的实例
# 直接覆盖会让占位符 {{LANGUAGE_BACKEND}} 等回归 → validate.sh 报错
# 解法：rules 文件名遍历，只对 tech-stack-rules.md 例外保留
for rule_file in $HARNESS_LITE_ROOT/templates/.claude/rules/*.md; do
    if [ "$fname" = "tech-stack-rules.md" ]; then
        # 已渲染过的实例文件——保留用户当前内容
        :
    else
        cp -f "$rule_file" ".claude/rules/$fname"
    fi
done
```

→ 设计阶段没考虑到这个细节，是测试时被 validate.sh 抓到的。**这正是 validate.sh 的兜底价值**。

### CLAUDE.md sed 替换（仅头部版本号）

```bash
# 不重写 CLAUDE.md（保留用户加的内容），只替换 "v{OLD} 生成" → "v{NEW} 生成"
sed -i.bak -E "s#v${OLD_VERSION//./\\.}( 生成)#v${NEW_VERSION}\1#" CLAUDE.md
```

注意：转义点号 `${OLD_VERSION//./\\.}`，否则正则会把 1.0.4 当成"任意字符 0 任意字符 4"误匹配 v100x4。
