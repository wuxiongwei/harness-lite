# 决策学习协议使用指南（v1.0.21+）

> 适用：装了 Harness-Lite v1.0.21 及以上的用户。
> 5 分钟读完。

---

## TL;DR

- AI 遇到决策点会**老实问**，**老实记**到 `.claude/decision-log.md`
- 走完一次 path-a 到 05-完成 时，AI 会**批量复盘**：列出本次被问的所有决策，让你一次性授权
- 被授权的决策写入 `.claude/auto-decide.md`，**下次同场景 AI 不再问，直接用**
- 自决时产物末尾会标注 `ℹ️ 已使用 AI 自决项`，含**撤回路径**

---

## 1. 为什么有这个协议

**老问题**：每次走 path-a，AI 都问类似"表格用 Markdown 还是 HTML"——你已经答过 N 次。

**两种极端**：
- 问太多 → 你疲劳
- 不问 → AI 决策可能偏离你的偏好

**解决方案**（v1.0.21）：**老实问 + 老实记 + 批量复盘**。让 AI 学会你的偏好，但**学习时机由你掌控**。

## 2. 完整使用流程

### 2.1 第一次走 path-a（场景：v1.0.x 新需求）

```
你：/harness-req 加一个搜索功能
   ↓
AI 走 Phase 1-4，遇到 N 个决策点
   ↓
每个决策点 AI 问你：
   🤔 用户故事粒度选哪种？
      [1] 粗粒度
      [2] 细粒度  
      [3] 中等粒度
   请选择：2
   ↓
AI 记录到 .claude/decision-log.md（你看不到也没关系，AI 在管理）
   ↓
继续 Phase 5 / 6
```

### 2.2 走到 05-完成 阶段（关键：批量复盘）

```
你：进入阶段 5 写 05-完成.md
   ↓
AI 自动检查 .claude/decision-log.md
   ↓
本次迭代有 5 条待复盘 → 触发对话：

🔍 本次迭代被询问的决策（5 条）：

[1] 用户故事粒度（你选了 细粒度）
[2] 表格格式（你选了 Markdown 表）
[3] 模块拆分粒度（你选了 不拆）
[4] AC 数量（你选了 每 US 3 条）
[5] 不做范围位置（你选了 独立章节）

对每条选择处理：
- [a] 以后别问（写入 auto-decide）
- [s] 继续问（保留询问）
- [d] 删除记录（不学习）

请输入：1=a,2=s,3=a 或 all=a 或 quit
   ↓
你：1=a,2=a,3=s,4=a,5=a
   ↓
AI 写 .claude/auto-decide.md：4 条已授权
保留询问：第 3 条（模块拆分粒度，每次项目特性不同）
```

### 2.3 下次走 path-a（场景：v1.0.x+1 新需求）

```
你：/harness-req 加一个收藏功能
   ↓
AI Phase 5.5 决策点处理：
  - 遇到"用户故事粒度"决策 → 查 auto-decide → 命中 → 自动用"细粒度"
  - 遇到"模块拆分粒度"决策 → 查 auto-decide → 未命中 → 询问你
   ↓
产物末尾：

---
> ℹ️ 本产物已使用 AI 自决项：
>   - 用户故事粒度：细粒度（撤回：编辑 .claude/auto-decide.md）
>   - 表格格式：Markdown 表（撤回同上）
>   - AC 数量：每 US 3 条（撤回同上）
>   - 不做范围位置：独立章节（撤回同上）
```

## 3. 三个文件你必须知道

### 3.1 `.claude/decision-log.md`（AI 管理）

> 每次 AI 问你决策都追加到这里。**默认 .gitignore，不入团队仓库**。

格式：
```markdown
## 2026-06-18 14:30 · v1.0.21-lite-automation · path-a/01-需求 · 用户故事粒度
- 问题：用户故事粒度选哪种？
- 选项：[粗粒度 / 细粒度 / 中等粒度]
- 用户答：细粒度
- 关键词：path-a, 01-需求, 用户故事, 粒度
- 状态：⏳ 待复盘 / ✅ 已授权 / 🔁 保留询问 / 🗑 已删除
```

### 3.2 `.claude/auto-decide.md`（AI 管理 + 你可编辑）

> 已授权清单。**默认 .gitignore，不入团队仓库**。

格式：
```markdown
## ✅ 用户故事粒度（授权 2026-06-18 v1.0.21-lite-automation）
- 关键词（必须**全部**命中才自决）：path-a + 01-需求 + 用户故事 + 粒度
- 自动选择：细粒度
- 来源：decision-log.md @ 2026-06-18 14:30
```

**撤回方式**：编辑此文件，删除整段。下次同场景 AI 恢复询问。

### 3.3 `.claude/principles.md` §13（协议本身）

不需要你看——但如果好奇 AI 内部如何工作，可以读。

## 4. 批量授权对话语法

| 语法 | 含义 |
|-----|------|
| `1=a,2=s,3=a` | 第 1 条授权、第 2 条保留询问、第 3 条授权 |
| `all=a` | 全部授权 |
| `all=s` | 全部保留询问 |
| `1=d,2=a` | 第 1 条删除记录、第 2 条授权 |
| `quit` | 全部不动（下次仍触发对话） |

---

## 5. 三个状态码

| 状态 | 含义 | 下次场景行为 |
|-----|------|-------------|
| `[a]` 以后别问 | 授权 AI 自决 | 写 auto-decide → 下次自动用此选择 + 标注 |
| `[s]` 继续问 | 保留询问 | 不写 auto-decide → 下次仍触发对话 |
| `[d]` 删除记录 | 不学习 | 从 decision-log 删除 → 下次首次询问（无"上次你选 X"提示） |

## 6. 安全保障

### 6.1 偏好不能覆盖铁律

`principles.md` §1-§12 是铁律，**偏好不能覆盖**：
- ❌ 你授权"AI 主动 commit" → AI 拒绝写入（违反 §8）
- ❌ 你授权"跳过测试" → 拒绝（违反 §11）
- ❌ 你授权"引出语后停止" → 拒绝（违反 §12）

AI 拒绝时显式提示："此决策违反 principles §X，不可授权"。

### 6.2 文件不存在 = v1.0.20 行为

如果 `.claude/auto-decide.md` 不存在 → AI 直接询问每个决策点，**等同 v1.0.20 行为**。

### 6.3 严格匹配（不会误命中）

AI 检查 auto-decide 是**严格匹配**——条目里的关键词必须**全部**在当前场景出现。任一缺失 = 不命中 = 仍询问。

宁可错问，不可错决。

## 7. 手动触发复盘

不一定等到 05-完成 才复盘。任何时候你都可以：

```
你：复盘一下决策
   ↓
AI 立即触发批量授权对话（同 §2.2）
```

也可以说"review decisions"。

---

## 8. 撤回授权

```bash
# 方法 1：编辑文件删条目
$EDITOR .claude/auto-decide.md
# 找到对应条目，删整段

# 方法 2：清空文件（撤回全部）
rm .claude/auto-decide.md
# 下次 AI 行为 = v1.0.20（每次都问）
```

下次同场景 AI 恢复询问 + 记 decision-log。

## 9. FAQ

### Q1：AI 没问我决策点，直接动手了，正常吗？
A：可能两种：
- 此决策已被授权 → 产物末尾应标注"已使用 AI 自决项"
- AI 没识别到这是决策点 → 下次明确告诉 AI"这里有 ≥ 2 个合理选项，问我"

### Q2：误授权了怎么办？
A：编辑 `.claude/auto-decide.md` 删条目。下次 AI 恢复询问。

### Q3：换项目时偏好会跟过来吗？
A：**不会**。`.claude/auto-decide.md` 在项目内（`.claude/` 目录），不同项目独立。

如果想跨项目复用，手动 `cp`（v1.2 可能加导入/导出）。

### Q4：批量对话时我的输入语法错了怎么办？
A：AI 会提示有效语法 + 重新等待。`quit` 退出对话不写文件。

### Q5：decision-log 越写越大怎么办？
A：复盘后 AI 会自动清理已处理条目。如果你长期不复盘 → 手动清也行（不影响功能）。

### Q6：团队多人共用一个项目，偏好会冲突吗？
A：v1.0.21 默认偏好文件 `.gitignore`，**只在你本地**。不会冲突，但也不能共享。

如果想团队共享 → v1.0.22 Standard 档可能涉及（待规划）。

### Q7：principles §13 优先级最高吗？
A：**铁律 > 偏好**。`principles.md` 自身（§1-§12 + §13）即铁律，§13 自身规定"偏好不可覆盖铁律"。安全闭环。
