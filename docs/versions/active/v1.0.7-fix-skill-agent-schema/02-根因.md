# 02-根因.md · v1.0.7

> **路径C · 阶段2/4**

---

## 1. 直接根因

整个 `.claude/skills/` + `.claude/agents/` 目录的 frontmatter 用的是**自造 schema**（不是某个历史官方 schema，也不是任何标准），但 Claude Code 当前文档明确：
- skill 只认 14 个 frontmatter 字段（见 https://code.claude.com/docs/en/skills#frontmatter-reference）
- agent 只认 17 个 frontmatter 字段（见 https://code.claude.com/docs/en/sub-agents#supported-frontmatter-fields）
- skill 调用名 = 目录名（`harness-req/` → `/harness-req`），冒号是 plugin 专用

| 错的字段 | 实际语义 | 正确做法 |
|---------|---------|---------|
| `trigger.keywords` / `trigger.patterns` | 自动触发关键词 | 写到 `description` 里（Claude 通过 description 决定何时调用） |
| `version` | 版本号 | 不存在，删除（产品版本号已在 settings.json `_version`） |
| `visible:` / `invisible:` | agent 可见范围 | 删除——可见范围只能通过 `tools` / `disallowedTools` 限制工具，文件可见性是靠 system prompt 引导（不是 frontmatter） |
| `/harness:req` | 调用名 | 改 `/harness-req`（目录名已是连字符） |

---

## 2. 根因背后的根因（why this happened）

### 2.1 与 v1.0.5 完全同根

v1.0.5 的 `02-根因.md` 已写明："schema 凭印象写"。同一根因在 skill/agent 文件里**未被一并审计**——只关注了 settings.json。

**判断**：修 v1.0.5 时，应该把"凡是被 Claude Code 加载的元数据文件"全部翻一遍。当时只盯着报错信息修，没做横向扩展。

### 2.2 dogfooding 的盲区

skill/agent 的 frontmatter 错误**不会让 claude 启动报错**——Claude Code 对未知字段是"忽略 + 不警告"。所以即使在 stock 启动了 claude，问题也不会暴露。

**判断**：必须要有**主动 schema 校验**（v1.0.6 已经做了 settings.json 这部分），但漏了 skill/agent。

### 2.3 调用名搞错的"间接证据"

我把 `/harness:req` 写到所有文档里，但 dogfooding 期间**从来没真的在 claude 里敲过这个命令**——一旦敲过就立刻报 404。

**判断**：dogfooding 协议必须包含"装完 → 启动 claude → 敲一次 skill 命令验证"。

## 3. 修复方案

### 3.1 主修 · 5 个 skill frontmatter

每个 SKILL.md 重写 frontmatter：

```yaml
---
name: harness-req                  # 保留（仅作展示用）
description: |                     # 改写：把 trigger 的 keywords 融入 description
  Harness-Lite 主入口。当用户描述新需求 / 改文案 / 修 bug 时调用，
  自动判定路径（A 完整需求 / B 小需求 / C Bug 修复），生成第一阶段产物。
  关键词：新需求、改个、加一个、修复 bug、改文案、调配置、新增功能。
---
```

**删除**：`trigger` / `version` 整段。
**保留**：name + description（充实 description，把原本 trigger.keywords 的语义融入"何时调用"的描述）。

### 3.2 主修 · 4 个 agent frontmatter

每个 agent.md 重写 frontmatter：

```yaml
---
name: doc-generator
description: |
  文档生成专员（黑盒视角）。起草需求/设计/复现/根因文档。
  严格不读业务代码（src/main 等），只读需求和模板，避免"围绕实现写需求"。
tools: Read, Glob, Grep, Write, Edit
---
```

**删除**：`visible:` / `invisible:` 整段。
**新增**：`tools:` 列出该 agent 实际需要的工具（实现"可见范围"的正确方式）。
**保留**：约束语义——把"不读 src/main"等约束写到 frontmatter 之后的 system prompt body 里，让 LLM 看到。

### 3.3 全局替换 · 57 处 `/harness:` → `/harness-`

| 范围 | 处数 |
|-----|-----|
| `templates/.claude/skills/*/SKILL.md` | 49 |
| `templates/CLAUDE.md` | ~3 |
| `scripts/init.sh` | 1（"试跑第一个需求"提示） |
| `CLAUDE.md`（仓库根） | ~3 |
| `README.md`（仓库根） | ~1 |
| 历史版本目录 `docs/versions/active/v1.0.{1,2,3,5,6}-*/` | 不动（属于历史档，引用过去命令是事实记录） |

**用 sed 批量改**：`s|/harness:|/harness-|g`，但要绕开历史版本目录。

### 3.4 配套 · validate.sh 扩展 schema 校验

新增校验项：
- skill frontmatter 不含 `trigger:` / `version:`
- agent frontmatter 不含 `visible:` / `invisible:`
- skill description 长度提示（应 > 30 字，否则 Claude 不知何时触发）

### 3.5 现场修 · stock_make_money 同步

stock 端 `.claude/skills/` + `.claude/agents/` 直接覆盖 templates/ 内容（同步 v1.0.5 那次的处理方式）。

### 3.6 不做（避免过度治理）

- ❌ 不引入 yaml schema 校验工具（jq + 简单 grep 够）
- ❌ 不把 description 写得过长（控制 Claude 上下文消耗）
- ❌ 不为 skill 加 `disable-model-invocation`（让 Claude 自动触发是 Harness-Lite 的核心交互模式）

## 5. 与历史版本的关系

| 版本 | 类型 | 同根关系 |
|------|-----|---------|
| v1.0.5 | settings.json schema 漂移 | **直接姊妹 bug** |

→ **v1.0.7 完成后，validate.sh 必须把 skill/agent 校验也加上，让 v1.0.6 的自检体系真正完整覆盖三类元数据文件。**
