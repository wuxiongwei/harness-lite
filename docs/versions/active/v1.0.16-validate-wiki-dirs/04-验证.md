## 元发现

### M1 · validate.sh 防护层次

| 层次 | 检查什么 | 例子 |
|-----|---------|------|
| 文件存在性 | 关键配置文件 | CLAUDE.md / settings.json |
| 目录结构 | 产品架构必需目录 | .claude/templates/path-a / wiki 子目录 |
| Schema 正确性 | settings.json 6 条不变式 / skill frontmatter | v1.0.6 起 |
| 占位符渲染 | CLAUDE.md / rules 中无 `{{...}}` | v1.0.11 |
| Hook if 格式 | settings.json 中 if 字段带空格 | v1.0.12 |

→ **目录结构检查**是最基础的一层，但 v1.0.0-v1.0.15 只检查到 wiki 顶层，v1.0.16 补全到子目录级。

### M2 · "不过度"的边界判断

为什么不检查 wiki 子目录下是否有 .md 文件？
- wiki 内容是**用户/AI 逐步积累**的，不是安装时必须有
- v1.0.15 放的样例是"打样"，不是"强制标准"
- 检查"结构"（目录存在）≠ 检查"内容"（文件存在）

### M3 · validate.sh 进化史

| 版本 | 加了什么维度 | 累计维度数 |
|------|------------|----------|
| v1.0.0 | 文件 + 目录存在性 | 1 |
| v1.0.6 | settings.json schema（5 条不变式） | 2 |
| v1.0.7 | skill/agent frontmatter schema | 3 |
| v1.0.11 | 模板占位符扫描 | 4 |
| v1.0.12 | hook if 格式 | 5 |
| v1.0.16 | wiki 子目录结构 | 6（细化了第 1 维） |

→ validate.sh 是 H-L 防漂移网的**可视化实现**。
