## 1. 总体方案

`upgrade.sh` = `uninstall.sh 删 H-L 文件` + `init.sh 装 H-L 文件 + 不再问用户输入` + `渲染时复用旧 CLAUDE.md 的项目信息`。

但因为简化（不问输入），不能直接复用 init.sh——单独写一个。

```
[upgrade.sh 流程]
1. 前置检查：确认是 git repo + 当前已装 H-L（CLAUDE.md 含标识）+ 读出旧版本号
2. 与新版本对比 → 已最新就退出
3. 备份：.harness-lite-upgrade-backup/{ts}/.claude + CLAUDE.md
4. 提取项目信息：从旧 CLAUDE.md 头部回填 PROJECT_NAME / TAGLINE / TIER / TEAM_SIZE / TECH_STACK
5. 覆盖 H-L 管理范围：rules / skills / agents / hooks / templates / settings.json
6. 更新 CLAUDE.md 头部版本号字段（不重写整个文件 —— 用户可能加过内容）
7. 跑 validate.sh
8. 提示用户：已升级到 v{NEW}，旧版备份在 ...
```

## 2. 关键技术决策

### 决策 1：覆盖策略——简单粗暴

`init.sh` 已用 `cp -rn` (no-clobber，已存在不覆盖) 处理 skills/agents/hooks，但 upgrade 不能这样：必须**覆盖**才能拿到新版本。

```bash
# rules/skills/agents/hooks/templates 全部覆盖
cp -rf "$HARNESS_LITE_ROOT/templates/.claude/rules/."     ".claude/rules/"
cp -rf "$HARNESS_LITE_ROOT/templates/.claude/skills/."    ".claude/skills/"
# ...
```

**风险**：用户改过的 hook / skill 会被覆盖。
**缓解**：必有 backup；提示用户对比 backup 找回。
**遗留**：v1.1+ 引入 manifest.json + 选择性合并。

### 决策 2：CLAUDE.md 头部更新——用 sed，不重写整个文件

用户可能在 CLAUDE.md 加过自己的内容。upgrade 只更新顶部 6 行内的元信息：

```bash
# 模板头部模式（init.sh 渲染时填的占位符已被替换为真实值）
# 由 [Harness-Lite](https://github.com/zoe/harness-lite) v1.0.4 生成 · 安装时间：2026-06-16
sed -i.bak -E "s#v[0-9]+\.[0-9]+\.[0-9]+( 生成)#v${NEW_VERSION}\1#" CLAUDE.md
```

只改版本号 `v1.0.4` → `v1.0.8`，不动其他。

### 决策 3：从旧 CLAUDE.md 回填项目信息

`upgrade.sh` 不应再问用户名字 / 业务描述。当前不需要——因为我们只更新 H-L 管理的文件，CLAUDE.md 不重写。**TIER / TEAM_SIZE 等只在 init 时一次性渲染，升级时不再重渲染**。

→ 大幅简化：根本不需要"提取项目信息"这一步。从需求 §3 的 AC 看，CLAUDE.md 业务部分不动 = 不需要重渲染。

→ **设计修订**：upgrade.sh 不再做模板变量渲染。如果 settings.json 的 `_version` 是 `{{HARNESS_LITE_VERSION}}` 占位符，是新模板的副作用——单独 sed 替换即可。

### 决策 4：validate.sh 兜底

升级后必跑 validate.sh，失败就报警（不阻塞，但要让用户知道）。

### 决策 5：版本比较——纯字符串

`1.0.4` vs `1.0.8` 直接 string 比较够用（同一主版本内）。跨主版本（1.x → 2.x）届时单独处理。

```bash
if [ "$OLD_VERSION" = "$NEW_VERSION" ]; then
    log_info "已是最新版 v$NEW_VERSION"; exit 0
fi
```

## 4. 边界场景设计

| # | 场景 | 处理 |
|---|------|-----|
| 1 | `.claude/` 不存在（未装过） | exit 1 + 提示先跑 init.sh |
| 2 | CLAUDE.md 不含 "Harness-Lite" 字样 | 同上 |
| 3 | 旧版本号读不出（CLAUDE.md 没头部 / settings.json 损坏） | warn + 继续，按"未知版本"处理 |
| 4 | 已是最新版 | exit 0 + 提示 |
| 5 | 升级中途备份失败 | exit 1 + 提示磁盘 / 权限问题（绝不能在没备份的情况下覆盖） |
| 6 | 升级后 validate.sh 失败 | warn 但不回滚（手动从 backup 还原） |
