## 1. 直接根因

`scripts/upgrade.sh` 第 144 行：
```bash
local upgrade_date=$(date +"%Y-%m-%d")
```

`local` 关键字**只能在函数内使用**。这段代码不在函数内。

**macOS bash 3.2 行为**：
- 打印 stderr：`bash: line N: local: can only be used in a function`
- 单独运行：exit 0（不退出）
- **`set -e` 上下文中**：实测会**中断脚本**

后果：
- `upgrade_date` 变量未定义
- 后续 `for` 循环未执行
- `sed` 渲染未发生
- `set -e` 让 Step 5/6 也不执行

---

## 2. 根因背后的根因

### 2.1 `local` 写错的来源

写 v1.0.11 修复时，我把渲染逻辑当作"步骤4 内部子流程"来写——脑中模型是"在 Step 4 函数里加变量"。但 upgrade.sh 是**命令式脚本**，不是函数化结构——所有步骤都在主体里平铺。

**错把局部上下文心智模型套用到全局上下文**——这是写 bash 脚本时的常见陷阱。

### 2.2 v1.0.11 的"修复"从未在真实 upgrade 路径验证

v1.0.11 复盘里我写过：
> "测试 1 · 装完干净 / 测试 2 · 反向 / 测试 3 · stock 现场修复"

**没有"测试 4 · 真实跑 upgrade.sh"**！v1.0.11 后我手动 sed 修了 stock 的 domain-rules，没跑 upgrade.sh。

**这是 v1.0.13 dogfooding 协议升级的反例**——协议说"凡是被 Claude Code 加载的元数据/配置/hook 必须在真 claude 触发一次"，但**没明确说"凡是修脚本，必须在真实 trigger 路径跑一次"**。

### 2.3 同根第 6 次

| 版本 | 凭印象写的对象 | 检测点缺失 |
|------|-----------|----------|
| v1.0.5 | settings.json schema | 没读官方 docs |
| v1.0.7 | skill/agent frontmatter | 没读官方 docs |
| v1.0.11 | 占位符渲染规则 | 没跑真实 upgrade |
| v1.0.12 | hook if 字段 | 没读官方 docs |
| v1.0.13 | "已加入 backlog" | 没真写文件 |
| **v1.0.18** | **`local` 关键字位置** | **没跑真实 upgrade** |

→ 同一深度根因第 6 次出现：**"看起来对的代码 vs 真实跑过的代码"** 之间的差距。

## 3. 修复方案

### 3.1 主修

```diff
- local upgrade_date=$(date +"%Y-%m-%d")
+ upgrade_date=$(date +"%Y-%m-%d")
```

去掉 `local` 关键字。

### 3.2 横向预防

升级 v1.0.13 的 dogfooding 协议：
> 修脚本（init.sh / upgrade.sh / uninstall.sh / validate.sh）→ **必须在真实 trigger 路径完整跑一次**

加入 backlog/proposals.md（清欠 + 升级）。

### 3.3 现场修复

stock 端**真实跑一次 v1.0.18 upgrade.sh** 验证：
- v1.0.9 → v1.0.18 头部更新
- domain-rules.md 占位符渲染
- settings _version 从 1.0.12 → 1.0.18

### 3.4 不做（避免过度治理）

- ❌ 不重构 upgrade.sh 为函数化结构（成本大于收益）
- ❌ 不引入 shellcheck 静态检查（v1.1+ 视频率）
