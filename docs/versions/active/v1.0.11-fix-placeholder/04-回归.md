## 元发现

### M1 · 这是 v1.0.5 同根 bug 第 4 次出现

| 版本 | 表象 | 根因 |
|------|------|-----|
| v1.0.5 | settings.json schema 错 | 凭印象写 + 单点修改 |
| v1.0.7 | skill/agent schema 错 | 同上 |
| v1.0.8 | uninstall.sh 残留 | "加新东西忘了同步" |
| **v1.0.11** | **占位符未渲染** | **加新占位符忘了同步 init.sh** |

四次都是 "**点状改动没引发横向更新**"。已加入 backlog：写一份开发协议 "Adding-anything-checklist"——加新文件 / 新字段 / 新占位符 / 新 hook 时必须扫一遍相关同步点。

### M2 · validate.sh 防护体系完成第 4 维

| 维度 | 引入版本 | 抓什么 |
|-----|---------|-------|
| 文件存在性 | v1.0.0 | 关键文件 / 目录 |
| settings.json schema | v1.0.6 | 5 条不变式 |
| skill/agent schema | v1.0.7 | 废弃字段 / 缺 description / 旧调用名 |
| **模板占位符** | **v1.0.11** | **任何 CLAUDE.md / rules 残留 `{{...}}`** |

→ **第 4 维加入后，validate.sh 是 Harness-Lite 防同类回归的核心质量基础设施已经成型**。

### M3 · upgrade.sh 设计期的盲区

设计 upgrade.sh 时把 rules 文件分为"模板版 vs 已渲染实例版"两类，**漏掉了第三类**——"覆盖时是模板版，但需要立即渲染"（principles.md / domain-rules.md）。

→ 加入 backlog：v1.1+ 引入 manifest.json 时把"每个文件的生命周期"形式化（模板版 / 实例版 / 覆盖即渲染版）。
