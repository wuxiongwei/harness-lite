## 1. 总体架构

### 1.1 模块划分

```
src/
├── services/
│   └── search.py          # ⚠️ 与 alice v0.1-search-basic 共享文件
│       ├── basic_search()      # alice 写的（v0.1）
│       └── user_search()       # zoe 加的（v0.4）← 本次新增
├── api/
│   └── user_api.py        # 加 /search 端点
└── models/
    └── user.py            # 复用现有
```

**关键决策**：与 alice 协调——`user_search()` 复用 `basic_search()` 的 LIKE 实现，不引入 ES。

### 1.2 数据流

```
HTTP /api/user/search?q=alice&fields=name,email
    ↓
user_api.search()
    ↓
search.user_search(query, fields)
    ↓
db.query("SELECT ... FROM users WHERE name LIKE ? OR email LIKE ?")
    ↓
return list[User]
```

## 2. 关键决策

| # | 决策项 | 选项 | 选择 | 理由 |
|---|-------|------|------|------|
| D1 | 搜索实现 | LIKE / ES / Trigram | **LIKE** | 复用 alice v0.1，避免引入 ES |
| D2 | 字段选择 | 固定字段 / 动态参数 | **动态参数** | 灵活性，未来扩展 |
| D3 | 模糊匹配位置 | 前缀 / 包含 / 后缀 | **包含**（`%q%`） | 用户习惯 |
| D4 | 性能阈值 | 200ms / 500ms / 1s | **500ms** | 平衡用户体验与实现 |

## 4. 异常处理

| 场景 | 处理 |
|-----|------|
| 空查询 | 返回 400 + "query 不能为空" |
| 超长查询（>200 字符）| 截断到 200 + warn log |
| 无结果 | 返回 200 + 空列表（不 404） |
| 数据库超时 | 返回 504 + 错误日志 |

## 🔍 协同视角（v1.0.23+）

### 📝 PM 视角（用户价值 / 需求回应）
- ✅ **回应需求**：用户故事 US1 的"按用户名 / 邮箱 / 手机号搜"已对应 D2 动态字段参数
- ⚠️ **未做范围**：01-需求.md "不做"中明确"不支持 emoji"——D3 的 `%q%` 包含匹配下，emoji 输入会被原样匹配（不报错但无结果），符合预期
- ⚠️ **用户价值**：D4 选 500ms 阈值，对前端搜索框输入的实时反馈可能偏慢，建议 PM 验证用户能接受

### 🧪 QA 视角（可测性 / 测试设计）
- ✅ **可测性**：3 个函数（user_search / api endpoint / db query）每个都有清晰输入输出
- ⚠️ **测试边界缺位**：异常处理表只列了 4 种，**遗漏**：用户名含 SQL 元字符（`%` `_`）的转义、并发同时搜索的死锁
- ⚠️ **性能验证方法**：D4 的 500ms 阈值需要在 1000 用户数据集 + 100 并发下验证——本设计未指定测试方法
- ⚠️ **回归风险**：alice 的 v0.1 `basic_search()` 单测必须不因本次改动失败 → 需要在 04-测试.md 加"alice v0.1 全用例回归"
