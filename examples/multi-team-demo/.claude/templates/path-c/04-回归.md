## 5. 反向校验

- [ ] **场景还原**：是否回到了 01-复现 的原始场景？

- [ ] **同类完整**：所有同类入口都验证过？
- [ ] **副作用**：修复是否影响了其他功能？

## 6. 知识沉淀（路径C必做！）

⚠️ Bug修复是知识沉淀的最佳时机：

- [ ] **写入 pitfall**：必须 → `team-knowledge/wiki/pitfalls/{编号}-{标题}.md`
  - 包含：触发场景 / 根因 / 修复方式 / 预防规则

- [ ] **更新 domain-rules**：是否需要加业务铁律？
  - 是 → 追加到 `.claude/rules/domain-rules.md`
  - 否 → 跳过

- [ ] **更新 tech-stack-rules**：是否需要加技术栈规则？
  - 是 → 追加到 `.claude/rules/tech-stack-rules.md`
  - 否 → 跳过
