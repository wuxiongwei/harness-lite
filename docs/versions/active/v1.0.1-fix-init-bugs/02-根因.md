## Bug #1：sed 转义错误（P0，已修）

### 直接原因（What）
```bash
sed -e "s|{{TECH_STACK}}|$TECH_STACK_BACKEND \\\\| $TECH_STACK_FRONTEND \\\\| $DATABASE|g"
```
4个反斜杠 `\\\\` 被 shell 解释为2个 `\\`，再被 sed 解释为1个 `\`，但分隔符也是 `|`，导致 sed 把 `\|` 当成普通字面量却又触发了"bad flag"错误。

### 根本原因（Why）
**用 `|` 作为 sed 分隔符 + 试图在替换值中输出 `|` 字符** = 转义死循环。

### 设计/流程缺陷（Why-Why）
我在写 sed 时同时做了两件事（选了 `|` 分隔符 + 替换值含 `|`），违反了"sed 分隔符要选不会出现在替换值中的字符"这条工程经验。

## Bug #2：uninstall 后 .claude/ 残留

### 直接原因
uninstall.sh 末尾只 rmdir 了 `.claude/skills` `.claude/agents` 等子目录，**没 rmdir `.claude/` 本身**。

### 根本原因
`rmdir` 只删空目录，所以理论上 `.claude/` 子目录都删完后再 rmdir `.claude/` 是安全的（如果用户没有自己的文件就删，有的话保留）。原代码漏写了这一行。

### Why-Why
写 uninstall.sh 时没有"测试卸载是否干净"的验证步骤，导致这个简单遗漏没被发现。

## Bug #3：unary operator 错误

### 直接原因
```bash
# install_templates() 内
local needs_backup=0
# print_next_steps() 内
if [ $needs_backup -eq 1 ]; then  # ← needs_backup 是局部变量，访问不到
```

### 根本原因
Bash 函数的 `local` 作用域问题。变量在不同函数间需共享时，应该用全局变量，或通过 return code/参数传递。

### Why-Why
对 Bash 作用域不够熟悉。每个函数都用 `local` 是好习惯，但跨函数共享状态时要切换为全局。

## Bug #4：banner ANSI 转义未生效

### 直接原因
```bash
YELLOW='\033[1;33m'  # 单引号，字面量
cat << EOF
... ${YELLOW}xxx${NC} ...    # cat 不解释 \033 为 ESC
EOF
```

### 根本原因
`cat << EOF` 会展开变量，但**不会解释 `\033` 为 ANSI ESC 字符**。`echo -e` 才会解释。所以 `${YELLOW}` 展开为字符串 `\033[1;33m` 后，cat 直接输出，终端看到的是字面量。

### Why-Why
两种修复路径：
- A. 改用 `printf "%b" "${YELLOW}..."` 或 `echo -e`
- B. 简化 banner 不用颜色（已选 ✅）

选 B 的原因：banner 信息密度低，没必要彩色。简化反而更清爽。

## 修复方案对比

### Bug #1 修复方案
| 方案 | 优势 | 劣势 |
|------|------|------|
| A. 把分隔符改为 `#` | 简单直接 | sed 在 `#` 出现时仍可能冲突 |
| B. 把替换值的 `|` 改为 `/` | 不冲突 | Markdown 表格变形 |
| **C（已选）：分隔符 `#` + 替换值 `/`** | **彻底无冲突** | - |

### Bug #2 修复方案
**已选**：在 uninstall.sh 末尾加 `rmdir ".claude" 2>/dev/null && log_success ... || log_info ...`，并 log 提示用户结果。

### Bug #3 修复方案
**已选**：把 `local needs_backup` 改为全局 `INSTALL_HAD_BACKUP`，命名加前缀避免与未来其他全局变量冲突。

### Bug #4 修复方案
**已选**：简化 banner（去掉 ANSI 颜色，改用 echo + log_info 组合），保持信息但不依赖颜色。
