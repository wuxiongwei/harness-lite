## 元发现

### M2 · 软约束 + 示例 = 协议层产品的关键

| 强度 | 实施成本 | 效果 |
|-----|---------|------|
| 软约束（描述） | 极低 | ❌ 不触发 |
| **软约束 + 示例**（v1.0.24）| 低 | ✅ 触发（已实证）|
| 中约束（Phase checklist） | 中 | （未做，留备份）|
| 强约束（Hook 拦截） | 高 | （未做）|

→ **加示例纲领**这一步本来很简单，但是是协议层产品**真能落地**的关键一步。

### M3 · dogfooding 价值再次实锤

```
v1.0.21 协议落地 → 没用 example 验证
v1.0.22 文档配套 → 没用 example 验证
v1.0.23 §14 落地 → 用户要求才用 example 验证
v1.0.24 修 M1 → example 暴露 0 条 log，启动修复
```

→ **每次大协议改动都应当 dogfood**——不 dogfood = 等用户反馈才发现 gap。

加入 backlog/proposals.md：协议层版本必须 dogfood。

### M4 · v1.0.24 顺手修了符号链接边界 bug

不是本次的目标，但 dogfooding 时（创建 .claude/decision-log.md）发现 .gitignore 规则被符号链接绕过，导致 log 文件入仓。

**两个值得沉淀**：
1. 符号链接 + .gitignore 是常见陷阱
2. **dogfooding 顺手暴露周边 bug**——这是 dogfooding 的副产品价值
