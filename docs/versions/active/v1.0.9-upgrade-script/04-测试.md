## 元发现

### 设计阶段的盲区——被 validate 抓到

设计时把 rules/ 当作"H-L 标准管理"——直接覆盖。但 `tech-stack-rules.md` 在 init.sh 里被渲染为用户实例文件（含 backend/frontend/database 真实值），**它在生命周期中是实例文件，不是模板文件**。

→ validate.sh 抓出这点是关键的兜底——证明 v1.0.6/1.0.7 加的 schema 校验体系**有真实价值**。

### 写脚本时小但持续踩的坑：bash 多字节边界

中文紧跟 `$VAR` 在 macOS bash 3.2 下会导致截断。已遇到 4 次（v1.0.4 / v1.0.5 / v1.0.9）：
- v1.0.4：`read -p "项目名（默认 $X）"` → 显示 ��
- v1.0.5：echo 中文 + ANSI 颜色码混用
- v1.0.9：`log_success "已是最新版 v$NEW_VERSION，无需升级"` → "已是最新版 v�"

→ 通用解法：**`$VAR` 用 `${VAR}` 大括号显式分界**。已加入 backlog 作为 bash 编码守则。
