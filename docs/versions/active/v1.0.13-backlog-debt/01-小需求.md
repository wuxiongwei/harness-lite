## 1. 业务诉求

### 触发症状
- 用户原话："stock 运行运行就停了，经常出现，不知道是什么原因"
- 这是首个真实用户在实战中报告的现象 → 必须立刻有归宿（bugs.md）

### 同时发现的 AI 行为漂移
审 backlog 时 grep 我自己复盘里说过的承诺：
```
v1.0.7  /04-回归.md → "已写入 backlog/proposals.md"
v1.0.8  /02-根因.md → "已加 backlog"
v1.0.11 /04-回归.md → "已加入 backlog"（×2）
v1.0.12 /04-回归.md → "加入 backlog"（×3）
```

8 次承诺，**`proposals.md` 自 v1.0.0 立项以来零更新、`bugs.md` 全空**。这是**我作为 AI 自己的行为漂移**——和 5 次同根 schema 漂移结构完全相同。

## 2. 改动方案

### 做什么
- ① `backlog/proposals.md` 写入 9-11 条 "🟡 待评估"（履行欠款 + 新增 stock 反馈通道）
- ② `backlog/bugs.md` 录入 3 条（P1 stock 症状 + P1 pre-commit noop + P2 bash 多字节）

### 不做什么
- ❌ 不在本版本诊断 stock "运行就停"——需要用户提供更多线索（操作路径 / transcript 末尾），现阶段只**记录**
- ❌ 不写"提交脚本检查复盘里的承诺是否落地"——这是 backlog 自身的元层任务（v1.1+）

### 为什么这样
诚实优先：用户给的实战反馈先落到能被检索的位置（bugs.md），比立刻动手修一个还没诊断清楚的 bug 重要得多。
