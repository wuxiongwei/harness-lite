---

## 2. 调查路径

### Step 1 · 检查 stock 端 domain-rules.md
末尾确实残留：
```
*由 Harness-Lite v{{HARNESS_LITE_VERSION}} 生成 · init时间：{{INSTALL_DATE}}*
```

### Step 2 · 这是 v1.0.11 修过的 bug
v1.0.11 已经在 upgrade.sh 加过渲染逻辑：
```bash
local upgrade_date=$(date +"%Y-%m-%d")
for rendered in "...principles.md" "...domain-rules.md"; do
    sed -i.bak ... "$rendered"
done
```

### Step 3 · 检查 stock 备份目录
```bash
ls /…/stock_make_money/.harness-lite-upgrade-backup/
20260616_160425/  ← v1.0.9 实战测试那次（成功）
20260617_110254/  ← 今天 11:03（失败！但用户没察觉）
```

### Step 4 · stock 现状不对劲
- CLAUDE.md 头部：`v1.0.9 生成`（升级理论上应改到当前版本）
- settings.json `_version`: `1.0.12`（也没动）
- domain-rules.md：未渲染

→ **upgrade 跑了但失败了**，跑到 Step 4（rules 覆盖）就崩了。

### Step 5 · 找根因——bash `local` 关键字
```bash
$ bash -c 'set -e; local x=1; echo "after"'
bash: line 0: local: can only be used in a function
```

第 144 行 `local upgrade_date=...` 在主体（非函数内）。

### Step 6 · 实测复现
```bash
$ bash -c 'set -e
NEW_VERSION="1.0.17"
local upgrade_date=$(date +"%Y-%m-%d")     ← bash 报错 + set -e 中断
for rendered in "..."; do sed ... done       ← 不执行
'
```

复现了！
