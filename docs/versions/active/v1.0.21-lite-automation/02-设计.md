## 3. 模块设计

### 3.1 协议层 · principles.md §13

新增章节 "决策学习协议"，4 段：

```markdown
## 13. 决策学习协议（v1.0.21 起）

### 13.1 决策点定义
"决策点" = AI 在生成产物时，对一个有 ≥ 2 个合理选项的子问题需要拍板。

### 13.2 必记清单（AI 必须记录的决策类型）
- 文档格式（表格 / 列表 / 缩进风格）
- commit message 格式
- 测试框架命名规范
- 模块拆分粒度
- 数据结构选择（dict vs dataclass vs class）
- 异常处理风格（exception vs result）
- 命名风格（驼峰 vs 蛇形）
- ...（项目可在 domain-rules.md 扩展）

### 13.3 处理流程
1. 遇决策点 → 查 .claude/auto-decide.md
2. 命中关键词 → 自决 + 在产物末尾标注（含撤回路径）
3. 未命中 → 显式问用户（列选项）
4. 记录到 .claude/decision-log.md（追加）

### 13.4 复盘触发
- 自动：进入 path-a 阶段 5（05-完成.md）时
- 手动：用户说 "复盘决策" / "review decisions"

### 13.5 与铁律的优先级
偏好不能覆盖 principles 已列铁律（§1-§12）：
- 例：用户授权"主动 commit" → **拒绝写入** auto-decide
- 例：用户授权"跳过测试" → **拒绝写入**
拒绝时 AI 显式提示："此决策违反 principles §X，不可授权"
```

### 3.2 数据层 · 文件 schema

#### `.claude/decision-log.md`

```markdown
# 决策日志

> v1.0.21+ AI 每次询问决策都追加到此

---

## YYYY-MM-DD HH:MM · {版本ID} · {阶段} · {简短标题}
- 问题：{完整问句}
- 选项：[选项 A / 选项 B / 选项 C]
- 用户答：{选中的选项}
- 关键词：{kw1, kw2, kw3}
- 状态：⏳ 待复盘 / ✅ 已授权 / ❌ 已拒授权 / 🗑 已删除

---
（追加新条目）
```

**字段语义**：
- 时间戳精确到分钟（同一分钟内 N 条按顺序追加）
- "版本ID"用于复盘时**只取本次迭代条目**（如 `v1.0.21-lite-automation`）
- "关键词"3-5 个，用于后续匹配
- "状态"复盘后由 AI 写回（已授权/已拒/已删）

#### `.claude/auto-decide.md`

```markdown
# AI 自决清单

> 用户授权 AI 在以下场景自动决策

## 撤回方式
编辑本文件，删除对应条目。下次同关键词场景将恢复询问。

---

## ✅ 表格格式（授权 2026-06-17 v1.0.21）
- 关键词（必须**全部**命中才自决）：02-设计 + 决策表 + 表格
- 自动选择：Markdown 表
- 来源：decision-log.md @ 2026-06-17 14:30

---
```

**严格匹配语义**：条目的关键词列表必须**全部**在当前决策点上下文中出现，才命中。任一缺失 → 不命中 → 仍询问。

`templates/templates/path-a/05-完成.md` 在"## 复盘要点"段后插入"## 决策回顾"段：

```markdown
## 决策回顾（v1.0.21+）

### 本次迭代被询问的决策

执行：
1. 读 `.claude/decision-log.md`
2. 过滤本次迭代条目（按"版本ID"字段）
3. 列出待复盘条目（状态 = ⏳ 待复盘）

如有 N > 0 条 → 触发批量授权对话：

\`\`\`
🔍 本次迭代被询问的决策（N 条）：

[1] {决策标题 1}（你选了 {选择}）
[2] {决策标题 2}（你选了 {选择}）
...

对每条选择处理：
- [a] 以后别问（写入 auto-decide）
- [s] 继续问（保留询问）
- [d] 删除记录（不学习）

请输入：1=a,2=s,3=a 或 all=a 或 quit
\`\`\`

### 用户选择处理

- 选 a → 写 auto-decide.md 一条 + 改 decision-log 状态为 ✅
- 选 s → 改 decision-log 状态为 🔁 保留询问（下次仍问）
- 选 d → 改状态为 🗑 已删除
- quit → 全部不动（下次仍触发）

### 清理 decision-log（D1 决策）

复盘后，将本次状态非 ⏳ 的条目从 decision-log.md 移除（保留追溯靠 auto-decide.md 的"来源"字段）。
```

## 4. 接口设计

### 4.1 决策日志写入

**输入**：决策上下文（问题 / 选项 / 答案 / 关键词 / 版本ID / 阶段）

**输出**：追加到 decision-log.md 的一条条目

**伪代码**：

```python
def append_decision_log(
    version_id: str,    # 如 "v1.0.21-lite-automation"
    phase: str,         # 如 "path-a/02-设计"
    title: str,         # 决策简短标题
    question: str,      # 完整问句
    options: list,      # 选项列表
    chosen: str,        # 用户选择
    keywords: list      # 关键词
):
    timestamp = now()
    entry = format_entry(...)
    append_to(".claude/decision-log.md", entry)
```

### 4.2 auto-decide 命中检查

**输入**：当前场景的关键词列表

**输出**：命中的条目（如有），含自动选择值

**伪代码**：

```python
def check_auto_decide(current_keywords: set) -> Optional[Decision]:
    decisions = parse(".claude/auto-decide.md")
    for d in decisions:
        if d.keywords.issubset(current_keywords):  # 严格匹配（D3）
            return d
    return None
```

### 4.3 批量复盘对话

**输入**：本次迭代的待复盘 decision 列表

**输出**：
1. auto-decide.md 追加用户授权条目
2. decision-log.md 状态更新或清理

**交互流程**：见 3.4 节模板。

## 5. 异常处理

| 场景 | 处理 |
|-----|------|
| `.claude/auto-decide.md` 不存在 | 视为空，所有决策点都问 |
| `.claude/decision-log.md` 不存在 | 首次写入时创建 |
| auto-decide 条目违反 principles 铁律 | AI 拒绝写入 + 显式提示 |
| 用户复盘对话中输入格式错（如"1=x"） | AI 提示有效格式 + 重新等待 |
| 多个条目关键词都命中（理论上严格匹配下不应发生） | 取第一条 + 警告"重复授权可能" |
| 偏好与项目硬约束冲突（如 domain-rules 规定 commit 格式 vs 用户偏好其他） | domain-rules 优先，偏好不生效 + 提示 |

## 6. 测试设计

### 6.1 单测点

| 模块 | 测试 |
|-----|------|
| append_decision_log | 字段完整 / 时间戳格式 / 追加不覆盖 |
| check_auto_decide 严格匹配 | 全命中→返回 / 缺一→不返回 / 多命中→第一条 |
| 复盘对话 | a/s/d 三种处理 / quit 不写文件 / 格式错误重提示 |
| principles 铁律保护 | 授权违反铁律→拒绝 |

### 6.2 集成测试场景

| 场景 | 步骤 | 预期 |
|-----|------|------|
| S1 完整 path-a 走一次 | req→design→code→test→complete | log 累积 N 条 + 完成阶段触发对话 |
| S2 自决匹配 | 第二次同场景 | 命中→自决+标注 |
| S3 关键词缺一 | 同决策但场景关键词减一 | 不命中→询问 |
| S4 撤回 | 删 auto-decide 条目 | 下次同场景恢复询问 |
| S5 铁律保护 | 用户授权"跳过测试" | AI 拒绝写入 |

## 7. 性能考量

| 操作 | 复杂度 | 性能 |
|-----|--------|------|
| 决策日志追加 | O(1) | < 5ms |
| auto-decide 匹配 | O(N×K) N=条目数，K=关键词数 | < 10ms（典型 < 50 条） |
| 复盘对话生成 | O(M) M=本次决策数 | 与 LLM 输出耗时一致 |

## 8. 兼容性设计

### 8.1 向下兼容（核心）

`.claude/decision-log.md` 和 `.claude/auto-decide.md` **不存在 = 等同 v1.0.20 行为**：

```python
# skill body 伪代码
auto_decide_path = ".claude/auto-decide.md"
if not exists(auto_decide_path):
    # v1.0.20 兼容路径：直接询问，不记日志
    return ask_user_directly(question, options)
else:
    # v1.0.21+ 路径
    return check_auto_decide_then_ask(...)
```

### 8.2 stock_make_money 升级路径

stock 装于 v1.0.20。升级到 v1.0.21 后：
- `.claude/decision-log.md` 不存在 → AI 行为不变
- 用户首次回答决策 → 自动创建文件
- 完成 path-a 时 → 触发首次复盘
- 渐进式启用，无 breaking change

## 9. 上线策略

### 9.1 dogfooding 优先

v1.0.21 自身（path-a 5 阶段）就是首个用户：
- 阶段 1（本文档完成阶段 1 时）已记录 1 条决策（"延迟批量回顾"方向 = 用户拍板，非 AI 询问，可手动补一条到 log）

### 9.2 stock 真实使用

stock upgrade 后正常用一次 → 第一次完成迭代触发复盘 → 收集真实使用反馈。
