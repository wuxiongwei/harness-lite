## 1. 业务诉求（来源）

来自 `v1.0.5-fix-settings-schema/04-回归.md` 的 3 条元发现：

> M1. validate.sh 应该校验 settings.json schema 是否能被 claude 加载
> M2. dogfooding 没暴露 schema bug 的根本原因——开发期没在装好的项目里启动 claude
> M3. 应该有"装完一键自检"

---

## 2. 改动方案

```
做什么：
  - validate.sh 增加 settings.json 关键字段 schema 校验（不依赖 claude，纯 jq）
  - init.sh 末尾新增明确提示："请立刻执行 claude 启动一次确认无 Settings Error"
  - 不引入额外工具/依赖（jq 在 macOS / Linux 默认或 Homebrew 都有）

为什么：
  - v1.0.5 暴露了"装完不启动 claude，schema 错了也不知道"的盲区
  - 不能依赖用户记住跑 claude——必须把这一步写进 validate.sh + init.sh 引导

怎么做：
  - validate.sh 加 schema_check() 函数：用 jq 校验 5 个关键不变式
  - init.sh print_next_steps() 把"启动 claude"提到 #1 必做项
```

## 5. schema 校验的 5 条不变式

| # | 不变式 | jq 表达式 |
|---|-------|----------|
| 1 | `permissions.allow` 是数组 | `.permissions.allow \| type == "array"` |
| 2 | `permissions.deny` 是数组 | `.permissions.deny \| type == "array"` |
| 3 | 没有遗留旧字段 `alwaysAllow` | `has("permissions") and (.permissions \| has("alwaysAllow") \| not)` |
| 4 | 每个 hook entry 的 `matcher` 是字符串 | `.hooks.PreToolUse[].matcher \| type == "string"` |
| 5 | 每个 hook entry 的 `hooks` 是数组 | `.hooks.PreToolUse[].hooks \| type == "array"` |

如果检测到 jq 不存在，**降级为 python json.tool**（基础语法）+ warn（提醒装 jq 才能完整校验）。
