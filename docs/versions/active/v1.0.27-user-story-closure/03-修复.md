## 关键代码

### principles.md §6.1

```markdown
### 6.1 用户故事真闭环硬约束（v1.0.27 起 · P0 铁律）

#### 6.1.1 报"完成"前必做的 3 个自问

[ ] 用户从哪里开始用这个功能？（入口在哪？）
[ ] 用户的中间路径是什么？（点哪个按钮 / 走哪个页面）
[ ] 用户最终看到什么？（结果是什么）

**任一答不出 → 未完成**。

#### 6.1.2 用户故事 = AC = 硬卡点

01-需求.md 的每条用户故事 / 验收标准（AC）都是"完成"的硬卡点。

**禁止行为**：
- ❌ "AC1 后端 API 已通" → 完成（缺前端→入口缺失→未闭环）
- ❌ "组件代码已写" → 完成（缺集成→入口缺失→未闭环）
- ❌ "测试通过" → 完成（测试 ≠ 用户路径）

**必做**：
- ✅ 每条 AC **真实演示**或**真实模拟**用户从入口到结果的完整路径

#### 6.1.3 后端 API + 前端集成的特殊情况

前端集成 = 把组件接到真实页面 / 路由。

**自检**：
[ ] 前端组件代码写完了？
[ ] 集成到哪个页面？
[ ] 路由注册了？
[ ] 真实环境能从用户入口走到这个组件？

四项任一缺失 → **未完成**。
```

### harness-review SKILL.md 维度6

```markdown
### 维度6：AC ↔ 用户路径真验证（v1.0.27 起）

检查每个 AC 是否真实可被用户走通：

检查项：
1. **用户入口识别**：用户从哪里开始？（哪个页面 / 按钮 / API）
2. **中间路径识别**：用户点击后发生什么？（前端交互 / 后端调用链）
3. **结果可观测**：用户最终看到什么？（页面变化 / 数据展示）
4. **端到端联调**：如果涉及前后端，二者是否真集成？

严格判定：
- ✅ 入口 + 中间路径 + 结果 三者全有 = 通过
- ❌ 任一缺失 / 只有代码但没集成 = 不通过

**此维度不通过 = P0 阻塞 = 禁止合并**。
```

### validate.sh 第 9 维

```bash
# 用户故事真闭环检查（v1.0.27）
for version_dir in docs/versions/active/*/; do
    req_file="$version_dir/01-需求.md"
    done_file="$version_dir/05-完成.md"

    # 01-需求 含用户故事 / AC → 05-完成 必须含"用户路径自检"段
    if grep -qE "用户故事|验收标准|AC" "$req_file"; then
        if [ -f "$done_file" ]; then
            if ! grep -q "用户路径自检" "$done_file"; then
                echo "✗ 缺'用户路径自检'段（§6.1 违规）"
                user_story_ok=false
            fi
        fi
    fi
done
```
