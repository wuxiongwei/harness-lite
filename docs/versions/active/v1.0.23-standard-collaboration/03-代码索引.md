## 4. 数据结构

### 4.1 branch-strategy.md 关键 schema

```markdown
## 命名规范
- feat/<short-name>      # 新功能
- fix/<short-name>       # bug 修复
- ...

## 主分支保护
- main：禁止直推

## 合并规则
- 必须 review
- 必须 pre-commit hook
```

### 4.2 assignments/<人>.md schema

```markdown
## 进行中（claimed）
### v0.X-<slug>
- claim 时间
- 状态
- 影响文件
- 协作者

## 待办（pending）

## 已完成（done）
```

## 5. 算法

### 5.1 分支命名检查（A1）

```python
def check_branch_name():
    if not exists(".claude/branch-strategy.md"):
        return  # v1.0.22 行为
    
    strategy = parse(".claude/branch-strategy.md")
    branch = git_current_branch()
    
    if not match_naming(branch, strategy.naming_rules):
        warn(f"⚠️ 分支 {branch} 不符规范，继续？(yes/rename)")
        # 用户选 yes → 继续 commit/push
        # 用户选 rename → 提示 git branch -m
```

### 5.2 任务冲突预警（A2）

```python
def check_task_conflict(target_version: str):
    if not exists(".claude/assignments/"):
        return  # v1.0.22 行为
    
    all_assignments = read_all(".claude/assignments/*.md")
    for person, claim_list in all_assignments:
        if target_version in claim_list:
            confirm = ask("⚠️ {person} 已 claim {target_version}, [1]协作 [2]改名 [3]取消")
            handle(confirm)
```

### 5.3 文件冲突预警（A3 · /harness-impact 扩展）

```python
def check_file_conflict():
    if not exists(".claude/assignments/"):
        return  # v1.0.22 行为
    
    my_changes = git_diff_names()
    for person, claim in read_all_claims():
        if claim.in_progress:
            overlap = my_changes ∩ claim.affected_files
            if overlap:
                report.add_warning(
                    f"⚠️ 你改的 {overlap} 也被 {person} 在 {claim.version} 中 claim"
                )
```

## 7. 异常处理

| 场景 | 处理 |
|-----|------|
| `branch-strategy.md` 不存在 | 跳过分支检查（向下兼容）|
| `assignments/` 目录不存在或空 | 跳过冲突预警（向下兼容）|
| 多人 claim 同任务 | 多 owner 模式（D5）+ 双方都提醒 |
| 协同视角内容空 | AI 强约束 ≥ 2 条（防 R4）|
| 用户选"取消"（claim 冲突） | 不创建版本目录，回到对话 |
