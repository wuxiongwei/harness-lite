## 1. 业务背景与动机

### 1.1 用户场景

H-L Lite 档定位 1 人或小团队。当前（v1.0.20）的现实：
- AI 每次遇到决策点都问用户
- 用户答完就忘了"我答过什么"
- AI 第 N 次又问同样的问题
- 没有"学到了什么"的反馈闭环

### 1.2 v3 实时学习方案的问题

v3 设计 AI 在每次决策点都判断"该不该触发授权？"——**单次决策时 AI 与用户认知负担都重**：
- AI 要做"算 N 次 / 触发授权对话 / 写多文件"
- 用户每次都要看到"上次你选 X，这次也用？" + "要不要授权？"
- 信任度累积、匹配机制、阈值配置——全是设计复杂度

### 1.3 v4 延迟批量回顾的精妙

**AI 老实问、老实记，迭代结束时一次复盘 + 批量授权**：
- AI 单次决策时简单（不需要判断"该不该问"）
- 用户回顾时看全景（这次被问了 N 次，决定哪些以后别问）
- 触发时机显式（每次完成迭代 = 触发复盘）
- 跟 path-a 05-完成 阶段天然契合

### 1.4 与 path-a 的契合

05-完成.md 本来就是"复盘 + 沉淀"阶段。"**决策回顾**"自然作为复盘的一部分，不是平行的额外能力。

```
path-a 5 阶段：
  阶段 1-4 → AI 老实问 + 记 decision-log
  阶段 5 完成 → 复盘环节包含"决策回顾对话"
                ↓
                用户勾选"哪些以后别问"
                ↓
                写入 auto-decide.md
                ↓
                下次迭代 AI 匹配自决
```

### 1.5 不做的话会怎样

- AI 没有学习闭环
- 用户被反复问同样问题（疲劳）
- Lite 档没有真实价值升级

## 2. 功能需求

### 2.1 核心机制

| # | 功能点 | 说明 | 优先级 |
|---|-------|------|--------|
| F1 | 决策日志 | AI 每次问用户的决策，都追加到 `.claude/decision-log.md`（问题 + 选项 + 用户答 + 时间 + 场景） | P0 |
| F2 | 05-完成 阶段触发复盘 | 走 path-a 到 05-完成.md 时，AI 自动展示本次迭代被问过的所有决策 | P0 |
| F3 | 批量授权对话 | 用户对每条决策选"以后别问 / 继续问 / 删除记录" | P0 |
| F4 | auto-decide.md 写入 | 用户选"以后别问"的条目，写入 `.claude/auto-decide.md` | P0 |
| F5 | 自决匹配 | 后续 AI 遇到决策点，先查 auto-decide.md，命中则自决（用上次答案） | P0 |
| F6 | 自决标注 | 自决时显式标注产物："已按你的偏好自动选 X / 撤回：编辑 auto-decide.md" | P0 |
| F7 | 随时手动触发回顾 | 用户可以不等 05-完成，主动说"现在回顾一下决策"触发批量授权 | P1 |
| F8 | 撤回授权 | 用户编辑 auto-decide.md 删条目 → 下次该场景恢复询问 | P1 |
| F9 | 决策日志清理 | 复盘后用户可选"清空已处理的 decision-log 条目"（避免日志膨胀） | P2 |

### 2.3 05-完成 阶段的复盘对话

```
✓ path-a 5 阶段完成
✓ 进入 05-完成.md：复盘 + 沉淀

🔍 本次迭代被询问的决策（3 条）：

[1] 表格格式（你选了 Markdown 表）
[2] 模块拆分粒度（你选了 不拆）
[3] commit message 格式（你选了 feat: [模块] - ...）

对每条选择处理：
- [a] 以后别问（写入 auto-decide）
- [s] 继续问（保留询问）
- [d] 删除记录（不学习）

请输入：1=a,2=s,3=a 或 all=a 或 quit
```

用户输入后：
```
✓ 已写入 .claude/auto-decide.md：
  - 表格格式 → Markdown 表
  - commit message 格式 → feat: [模块] - ...

✓ 保持询问：
  - 模块拆分粒度（项目特性强相关，每次都问）

📝 撤回任何授权：编辑 .claude/auto-decide.md
```

### 2.4 后续自决时的产物标注

```markdown
# 02-设计.md
（产物内容）

...

---

> ℹ️ 本产物已使用 AI 自决项：
>   - 表格格式：Markdown 表（撤回：编辑 .claude/auto-decide.md）
```

### 2.5 非功能需求

| 维度 | 要求 |
|-----|------|
| 文件位置 | `.claude/decision-log.md` + `.claude/auto-decide.md` |
| 默认 .gitignore | 都不入团队仓库（个人偏好） |
| 透明 | 任何自决都标注产物，撤回路径显式 |
| 简化 | 不要"信任度阈值"、"复杂匹配"、"实时计数" |
| 与 path-a 契合 | 复盘嵌入 05-完成，不是独立模块 |

### 2.6 边界与约束

**做什么**：
- ✅ AI 老实问 + 老实记 decision-log
- ✅ 05-完成 阶段触发复盘对话
- ✅ 批量授权写入 auto-decide
- ✅ 自决时显式标注 + 撤回路径
- ✅ 关键词匹配（非 ML）

**不做什么**：
- ❌ 不做实时信任度累积（v3 已废）
- ❌ 不做"看用户输入预测偏好"——只记被询问的决策
- ❌ 不做匹配难（关键词命中即可，命中错了用户在下次复盘修正）
- ❌ 不做 ML / embedding
- ❌ 不做云同步
- ❌ 不做"组织级偏好继承"（v1.2 再说）
- ❌ 不强制清理 decision-log（用户自决，可选 F9）

## 3. 用户故事

### US1 · AI 老实问 + 老实记（P0）
```
作为 Lite 用户
我调 /harness-design 写 02-设计.md
```

**验收标准**：
- [ ] AI 显式列出选项
- [ ] 用户回答后，`.claude/decision-log.md` 追加一条

### US2 · 05-完成 阶段触发复盘（P0）
```
作为 完成迭代的用户
我让 AI 写 05-完成.md
我希望 在复盘段触发"决策回顾对话"
列出本次迭代所有被询问的决策
让我对每条选 [a=以后别问 / s=继续问 / d=删除记录]
```

**验收标准**：
- [ ] 05-完成 阶段 AI 自动读 decision-log
- [ ] 对话格式清晰、可批量操作（如"all=a"或"1=a,2=s,3=a"）
- [ ] 操作完成后，auto-decide.md 含已授权条目

### US3 · 自决与标注（P0）
```
作为 已授权用户
我调 /harness-design 写下一个 02-设计.md
AI 遇到表格格式决策（已授权）
我希望 AI 不问，直接用 Markdown 表
但产物末尾要列出"已自决项"清单
```

**验收标准**：
- [ ] AI 读 auto-decide.md，命中关键词
- [ ] 不显式问，直接产出
- [ ] 产物末尾含"ℹ️ 本产物已使用 AI 自决项"清单 + 撤回路径

### US4 · 手动触发回顾（P1）
```
作为 不一定走完整 path-a 的用户
我想 在任意时刻说"复盘一下决策"
让 AI 走批量授权对话流程
```

**验收标准**：
- [ ] 用户说"复盘决策"等关键词触发
- [ ] 读 decision-log 走对话流程
- [ ] 操作结果同 US2

### US5 · 撤回授权（P1）

## 4. 关键流程

### 4.1 阶段 1-4 期间（老实问 + 记）

```
AI 遇到决策点
  ↓
查 auto-decide.md
  ↓
命中？
├─ 是 → 自决 + 产物标注
└─ 否 → 显式问 + 记 decision-log
```

### 4.2 阶段 5 完成（触发复盘）

```
进入 05-完成.md
  ↓
读 decision-log（本次迭代内的）
  ↓
若有 N 条 → 触发复盘对话
  ├─ 显示决策清单
  ├─ 用户批量选择
  └─ 写 auto-decide.md
```

### 4.3 自决时的产物标注

```
产物末尾追加：

---
> ℹ️ 本产物已使用 AI 自决项：
>   - 表格格式：Markdown 表
>   - commit message 格式：feat: [模块] - ...
> 撤回：编辑 .claude/auto-decide.md
```

## 11. 元发现 · 4 次方向纠偏的方法论沉淀

| 版本 | AI 倾向 | 用户视角 |
|-----|--------|---------|
| v1 | 分工解决复杂度 | 不，要赋能 |
| v2 | 多视角解决复杂度 | 不，先分清 Lite 与 Standard |
| v3 | 复杂学习算法 | 不，简化 |
| v4 | （沿用 v3 复杂度） | **延迟批量** = 更优雅 |

**沉淀**：
- AI 解决问题倾向"加机制"
- 用户更倾向"少机制、更自然"
- **优秀产品方案 = AI 给方案 + 用户简化 + AI 学到该简化**

→ 加入 backlog/proposals.md："产品方案设计中用户视角的简化能力是 AI 学不到的关键"。
