## 1. 直接根因

`templates/.claude/settings.json` 用的是**过时的 schema**——既不是 Claude Code 当前版本期望的格式，也不是任何官方文档记载的历史格式，估计是早期开发时凭印象写的。

| 维度 | v1.0.4（错） | Claude Code 当前（对） |
|-----|------------|---------------------|
| permissions 字段 | `alwaysAllow` / `alwaysDeny` | `allow` / `deny` |
| permissions 条目 | 对象 `{"tool":"Bash","matchGlob":"git status*"}` | 字符串 `"Bash(git status:*)"` |
| hook matcher | 对象 `{"tool":"Bash","matchGlob":"git commit*"}` | 字符串 `"Bash"`（工具名） |
| hook 条目结构 | 平铺 `command`/`action` 在 entry 上 | 必须有 `hooks: [{type, command}]` 一层 |
| 命令模式过滤 | 用 `matchGlob` 字段 | 用 `if: "Bash(git commit*)"` |
| 阻塞机制 | 字段 `"action": "block_unless_pass"` | 脚本 `exit 2` + stderr |

---

## 2. 根因背后的根因（why we missed it）

### 2.1 缺少在真实 Claude Code 启动一次的验证

整个 v1.0.0~v1.0.4 的 dogfooding 全在 harness-lite **自己**目录里跑，但 harness-lite 自己的 `.claude` 是符号链接，且开发期一直没真在 harness-lite 里执行 `claude` 启动——只有 stock_make_money 这次首装才真正触发了 settings 加载校验。

**判断**：缺一个"装完后 claude 启动一次确认无报错"的验收步骤，光靠 `validate.sh` 检查文件存在性不够。

### 2.2 schema 凭印象写

写 settings.json 时没去查官方 schema，靠"以前用过的 hooks 文档印象"拍的。结果几个关键字段全错位：
- `alwaysAllow` 是早期某次设计稿的字段名（已废）
- `matchGlob` 是混淆了 file glob 与 tool matcher
- `action: block_unless_pass` 是自创字段名，Claude Code 从来没支持过

### 2.3 v1.0.2 加 pre-commit hook 时没二次校验

v1.0.2 把 `git commit` hook 从"仅提醒"改为"调用 pre-commit-test.sh"时，只改了 `command` 字段，**没察觉外层 schema 已经过时**。当时如果在装好的项目里启动一次 claude 就能立即看到报错。

## 4. 修复方案

### 4.1 主修

按 Claude Code 当前 schema 重写 `templates/.claude/settings.json`：

```json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "permissions": {
    "allow":  [ "Bash(git status:*)", ... ],
    "deny":   [ "Bash(rm -rf *)", "Edit(**/.env)", ... ]
  },
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          { "type": "command", "if": "Bash(git commit*)",
            "command": "bash ${CLAUDE_PROJECT_DIR}/.claude/hooks/pre-commit-test.sh" },
          { "type": "command", "if": "Bash(git push*)",
            "command": "bash ${CLAUDE_PROJECT_DIR}/.claude/hooks/block-push.sh" }
        ]
      }
    ],
    "PostToolUse": [
      {
        "matcher": "Write",
        "hooks": [
          { "type": "command", "if": "Write(docs/versions/active/**/04-*.md)",
            "command": "bash ${CLAUDE_PROJECT_DIR}/.claude/hooks/distill-prompt.sh" }
        ]
      }
    ]
  }
}
```

### 4.2 配套修

- **`pre-commit-test.sh`**：失败退出码 `1` → `2`（PreToolUse 阻塞约定）+ stderr 输出阻塞原因
- **新增 `block-push.sh`**：原本嵌入 settings 的"禁止 AI push" 逻辑独立成脚本（`exit 2`）
- **新增 `distill-prompt.sh`**：原本嵌入 settings 的"04-*.md 提示蒸馏"逻辑独立成脚本

### 4.3 现场修

stock_make_money 已装的 `.claude/settings.json` 同步覆盖（保持 hooks/skills 等其他文件不动）。

### 4.4 不做（避免过度治理）

- ❌ 不引入 JSON schema 自动校验工具（小项目不值，有 `claude` 启动报错就够）
- ❌ 不重做整个 hook 命名体系
- ❌ 不写 settings.json 的 unit test
