## 验证类型说明

### 静态用例（每次 push 自动跑）

- 文件结构完整性
- 文件格式正确性
- 黑名单关键词检查
- 版本号一致性

**执行方式**：`scripts/validate-static.sh`

### 行为用例（大改动后手动验证）

- skill 行为是否符合设计
- AI 是否正确响应 prompt
- 流程是否按预期流转

**执行方式**：人工启动典型场景，观察 AI 行为

### 真闭环用例（发布前在真实项目跑）

- 完整链路从头到尾跑一遍
- 在真实项目（如 stock-make-money）执行
- 验证用户故事真闭环（§6.1）

**执行方式**：真实项目 + 真实需求 + 真实验收

## 大改动定义

以下改动属于"大改动"，需要跑行为用例：

```
- 重构 skill Phase 流程
- 新增/删除 skill
- 修改核心规则（principles.md）
- 修改产物模板结构
- 修改 subagent 定义
```

以下改动属于"小改动"，只需跑静态用例：

```
- 改文案/改格式
- 修 typo
- 加注释
- 改示例内容
```

## 发布检查清单

发布新版本前，必须：

```
[ ] 静态用例全部通过（脚本跑）
[ ] 行为用例核心场景通过（手动跑 ≥ 3 个）
[ ] 真闭环用例至少 1 条通过（真实项目跑）
[ ] CHANGELOG 已更新
[ ] VERSION 已更新
```
