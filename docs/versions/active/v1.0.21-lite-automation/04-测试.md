## 3. 矩阵测试（T1-T9）

> 因决策学习是**协议层**实现（指导 AI 行为），无法用单元测试 / 自动化测试。这里用**推演 + 状态验证**模拟。

### T1 · 全新项目第 1 次问决策

**场景**：用户调 `/harness-req` 写需求，AI 遇到"用户故事粒度"决策点。

**状态前提**：`.claude/auto-decide.md` 不存在 / 不含相关条目。

**预期**：
1. AI 显式列出选项：`[1] 粗粒度 / [2] 细粒度 / [3] 中等粒度`
2. 用户答 `2`
3. AI 追加 `.claude/decision-log.md`：
   ```markdown
   ## 2026-MM-DD HH:MM · v1.0.21-lite-automation · path-a/01-需求 · 用户故事粒度
   - 问题：用户故事粒度选哪种？
   - 选项：[粗粒度 / 细粒度 / 中等粒度]
   - 用户答：细粒度
   - 关键词：path-a, 01-需求, 用户故事, 粒度
   - 状态：⏳ 待复盘
   ```

**实施层验证**：harness-req SKILL.md Phase 5.5 第 5 步描述了完整 schema ✅

---

### T2 · 同迭代再问别的决策

**场景**：T1 之后，AI 在 02-设计 阶段又问"表格格式"。

**预期**：decision-log.md **追加**第 2 条（不覆盖 T1 条目）。

**实施验证**：principles §13.2 流程图 + 5 skill body 都用"追加"语义 ✅

---

### T3 · 走到 05-完成 阶段触发批量回顾

**场景**：path-a 走到 05-完成.md，本次迭代有 3 条 decision-log 条目（状态 ⏳）。

**预期**：
1. 触发批量授权对话：
   ```
   🔍 本次迭代被询问的决策（3 条）：
   
   [1] 用户故事粒度（你选了 细粒度）
   [2] 表格格式（你选了 Markdown 表）
   [3] 模块拆分粒度（你选了 不拆）
   
   对每条选择处理：
   - [a] 以后别问（写入 auto-decide）
   - [s] 继续问（保留询问）
   - [d] 删除记录（不学习）
   
   请输入：1=a,2=s,3=a 或 all=a 或 quit
   ```

**实施验证**：05-完成.md 决策回顾段第 2 步对话格式与此完全一致 ✅

---

### T4 · 用户对 3 条选 [a, s, a]

**场景**：T3 用户输入 `1=a,2=s,3=a`。

**预期**：
- auto-decide.md 写入 2 条（用户故事粒度 + 模块拆分粒度，**注意**：表格格式是 s，不写入）
- decision-log 状态更新：
  - 第 1 条 → ✅ 已授权
  - 第 2 条 → 🔁 保留询问
  - 第 3 条 → ✅ 已授权
- 复盘后清理：第 1、3 条移除（D1 决策）；第 2 条保留（仍待复盘的状态切换为 🔁）

**实施验证**：05-完成.md 第 3-4 步流程描述完整覆盖 ✅

---

### T5 · 下次迭代同场景命中自决

**场景**：用户开新需求 `v1.0.22`，调 `/harness-req`，AI 又遇到"用户故事粒度"决策点。

**预期**：
1. AI 提取关键词：`{path-a, 01-需求, 用户故事, 粒度}`
2. 查 auto-decide.md：第 1 条关键词 `{path-a, 01-需求, 用户故事, 粒度}` ⊆ 当前关键词 → **命中**
3. AI 不询问，自决"细粒度"
4. 在 01-需求.md 末尾追加：
   ```markdown
   ---
   > ℹ️ 本产物已使用 AI 自决项：
   >   - 用户故事粒度：细粒度（撤回：编辑 .claude/auto-decide.md）
   ```

**实施验证**：principles §13.2 严格匹配 + §13.3 标注必做 + harness-req Phase 5.5 第 3 步 ✅
