## 4. 数据结构

### 4.1 decision-log.md schema

```markdown
## YYYY-MM-DD HH:MM · {版本ID} · {阶段} · {简短标题}
- 问题：{完整问句}
- 选项：[A / B / C]
- 用户答：{选中}
- 关键词：{kw1, kw2, kw3}
- 状态：⏳ 待复盘 / ✅ 已授权 / 🔁 保留询问 / 🗑 已删除
```

**关键字段**：
- 版本ID（如 `v1.0.21-lite-automation`）—— 复盘时只取本次条目
- 关键词（3-5 个）—— 严格匹配的依据
- 状态 —— 复盘后由 AI 写回

### 4.2 auto-decide.md schema

```markdown
## ✅ {决策标题}（授权 YYYY-MM-DD {版本ID}）
- 关键词（必须**全部**命中才自决）：{kw1} + {kw2} + {kw3}
- 自动选择：{选中值}
- 来源：decision-log.md @ YYYY-MM-DD HH:MM
```

**关键字段**：
- 关键词列表 —— 严格匹配
- 来源 —— 追溯 decision-log 原始记录

## 5. 算法

### 5.1 严格匹配算法

```python
def check_auto_decide(current_keywords: set) -> Optional[Decision]:
    """
    查 auto-decide.md，严格匹配当前场景关键词
    
    严格匹配 = 条目的关键词列表必须全部在 current_keywords 中出现
    """
    decisions = parse(".claude/auto-decide.md")
    for d in decisions:
        if d.keywords.issubset(current_keywords):
            return d
    return None
```

**复杂度**：O(N × K)，N = auto-decide 条目数，K = 平均关键词数。典型 < 50 条 → < 10ms。

### 5.2 复盘对话生成

```python
def generate_review_dialog(version_id: str) -> str:
    """
    读 decision-log，过滤本次版本 ID 的待复盘条目
    生成批量授权对话文本
    """
    log = parse(".claude/decision-log.md")
    pending = [d for d in log if d.version_id == version_id and d.status == "⏳"]
    if not pending:
        return "本次迭代无决策点询问"
    return format_dialog(pending)
```

| 场景 | 处理 |
